# 基金历史订单 CSV 与归档稳定性验收（2026-10-08）

本轮优化基金执行回放的输入和归档流程：历史订单可从 CSV 导入并逐笔核对，重复点击或网络重试不会新增同一请求的归档，损坏记录不会阻止其他记录读取。继续使用本机隔离环境，不使用 Docker，不切换正式环境，不安排长期后台验收。

## 功能与约束

选择 JSON 证据包后展开“从 CSV 导入历史订单”。模板包含 `submitted_at,signal_nav_date,action,amount,quantity` 五列，允许列顺序调整、引号字段、UTF-8 BOM 和常见换行格式。输入最多 1 MB、1,000 笔，金额和份额保留原始字符串，小数最多八位；不接受科学计数法、负值或含糊的申赎金额组合。

申购 `buy/add` 填正金额并留空份额，赎回 `sell/reduce` 填正份额，金额留空或为零。申请时间必须包含时区，按真实时间排序；信号净值日期必须早于北京时间申请日。错误标明原 CSV 行号。所有行校验成功后每页展示 20 笔；明确确认才替换草稿中的订单，保持日历、净值、费率与证据核对状态。待确认时禁用回放，账户切换或离开页面会清除草稿并拒绝迟到响应。

原生创建接口增加可选 `request_id`，格式为32位小写十六进制。客户端针对同一份已选草稿重复使用编号，修改草稿后使用新编号。服务端在计算前和事务提交时检查归档：首次成功返回201，重试返回200及原冻结内容，同编号不同证据返回409；已存请求的重试不受20份归档上限影响。并发提交只保存一份归档和一条创建审计。旧客户端省略编号仍按原行为创建。

归档读取验证结构、记录编号与内容指纹。结构异常和指纹错误返回409，隐藏结果；列表为损坏项返回数据库中的编号与记录时间、`integrity_valid=false`、`status=corrupted`，不采用损坏内容中的基金信息。页面禁用其查看按钮，保留删除入口；正常归档仍可读取和导出。

CSV 导入只处理当前证据包对应基金的订单，没有导入实际交易账本或自动交易。完整证据、申赎规则、未来信息及未支持的公司行为仍由原执行引擎校验；回放不取得策略准入资格。
