# 《02》阶段 A：取舍记录

本阶段按已批准设计在独立分支实施。保留原站主题、账户与基金/板块功能；不合并main、不部署。以下按作出顺序列出执行账本的全部取舍及代价。

1. 中证1000的行情映射核验通过，但产品清单仍为暂定。供应商身份不能证明原截图选项；代价是页面要保留暂定标签，不能宣称原图已确认。
2. 仓库只有 `QuantAssistant.Api.Tests`，Core注册表测试放入该既有项目，不创建计划中误写的Core.Tests。代价是测试项目名称覆盖Core与API两层，与原项目惯例一致。
3. 腾讯原响应不提供币种，`response_currency=null`，用注册定义和已核验命名空间说明币种依据。代价是需要响应币种字段的消费者不能把注册依据误当供应商字段；恒生科技Yahoo缺币种也未用作证据。
4. 新增模型字段使 `market_feed.py` 超过既有900行门禁，将六个原有观测数据类移入 `market_observations.py`，旧导入仍转出。代价是数据类实现模块改变；公开导入名称及JSON契约保留，没有放宽行数限制。
5. 缺失来源时间时 `observed_at/source_time=null`，保留真正接收时间。代价是DTO/前端时间类型可空、旧显示处需显示未知；有真实时间的响应不变。
6. 质量按指数分别判定，海外日历未知不把全部A股也标成过期。代价是消费者需要读取逐项状态，不能从集合 `stale=false` 推断所有项目都新鲜。
7. 同代码股票与指数使用 `(symbol, asset_type)` 身份键和不同适配路径。旧 `unavailable` 为兼容仍只含代码，新增稳定ID状态消除歧义；代价是同代码股票存在时，该代码的不同指数仍可能列在不可用数组中。
8. 原广度隔离测试将正常指数模拟为空，与如实报告空指数不可用冲突；改为正值合成指数并额外断言其存活，保留原不可用/过期断言。无产品行为代价，测试真正覆盖分区隔离。
9. 原生读取旧快照时仅对代码、名称、类型、市场、币种一致的行补权威身份，冲突行保留独立invalid状态。两个旧测试的虚构指数名称改为沪深300，价格及source仍为合成值，原断言保留。代价是新增供应商名称别称需要核验后更新注册表，不能静默重命名。
