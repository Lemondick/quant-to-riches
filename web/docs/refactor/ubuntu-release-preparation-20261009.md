# 观澜 Ubuntu 发布准备与本机验收

日期：2026-10-09。目标为用户已有的 Ubuntu 服务器、域名及证书，具体版本、架构和 SSH 地址尚未确认。本轮完成可部署交付和本机短时验收，未连接或切换正式服务器。

## 本轮变更

- Vue 与整个依赖树中的 SSR helper 升级至 3.5.43，消除 Vue SSR 已知漏洞。Uni-App 保留其支持的 3.4.21 编译器并显式传入，最终构建及浏览器兼容验证通过。旧组件测试模拟器补齐新版 Vue 使用的 DOM 方法和静态节点插入。
- `publish.ps1 -Target linux` 发布不带 Windows apphost 或 Windows Python 虚拟环境的便携 API。目标机按冻结的 Python 锁文件创建自己的环境。
- 增加 Linux 环境检查、现有证书 Caddy 示例和 Ubuntu 安装/迁移/备份/回退步骤。检查只报告先决条件，显式 `--sync` 才创建环境；非 Linux、缺 ASP.NET 运行时、旧 PG 客户端或安装失败时拒绝继续。
- API systemd unit 显式拉起三个 worker，配合 worker 对 API 的依赖和停止/重启关联。服务依赖合同测试通过，实际 systemd 故障恢复仍须在目标 Ubuntu 验证。
- 上一轮本机临时证书已到期，本次重新签发 localhost 测试证书并保留 CA 校验；测试证书及私钥不进入发布包。部署手册加入现有证书有效期和可读性检查。

| Shell / PowerShell | Bash 语法及 PowerShell parser 无错误 |

最终发布的 C# API 通过正常 CA 校验的 HTTPS 启动；三个真实 Python worker 达到就绪。验证回执归属、匿名 401、另一账户 404、重登录后相同回执；运行站点拒绝归档。丢失 worker 并过期心跳后返回 503，重新启动 worker 后返回 200；强制停止 API 后重启恢复相同回执。

实际停止并重新启动本机隔离 PostgreSQL，停库时 `/healthz` 返回 503，恢复后 `/readyz` 返回 200。将旧发布版启动在新的隔离库，再切回本次发布版，关键财务指纹和保存回执保持。

两次执行真实 custom dump 归档和新空库/新目录恢复，校验站点文件哈希、归档哈希绑定的恢复证明，并启动恢复副本的 API / 三个 worker。管理就绪 API 实际识别恢复证明；缺少正式域名证据仍阻止主机部署准入。

源站文件和原隔离财务事实保持；九张财务/审计表在本次隔离库与恢复库指纹一致，没有新增模型调用、报告或成交。故障期间的服务重启由本机验收脚本执行，不等同于已验证 Ubuntu systemd 自动重启。所有验收 API 与 worker 最后停止。

原始证据见本目录 `ubuntu-release-evidence-20261009.json`；交付包内含验收摘要、浏览器结果、依赖审计及文件 SHA256 清单，不含测试数据库归档、真实业务数据、凭据和证书。
