# 历史成交 CSV 批量导入与对账（2026-10-08）

已在交易账本增加“成交导入”入口，支持平台已经确认的基金、股票成交。用户先选择文件、逐笔核对、查看查重和整批回算结果，再明确确认入账；成功后下载逐笔回执并继续账户对账。本次继续本机隔离验收，无 Docker，无正式环境切换。

## 使用方法

1. 先保存完整账户基线，登记标的，并准备历史正式估值及原始审计证据。
2. 在“交易账本 → 成交导入”下载 UTF-8 CSV 模板，填写实际成交后选择文件。选择文件只读取本地草稿。
3. 填写核对依据，点击“查重并预览回算”。每页核对20笔成交，查看现金、持仓与历史净值；已有内容一致的成交跳过，编号冲突整批阻断。
4. 点击“确认整批入账”，在确认框再次核对。预览15分钟有效；账户、账本或估值来源变化后必须重新预览。
5. 下载逐笔导入回执；点击“继续账户对账”，选择平台快照、确认账户覆盖范围，填写费用期间及平台费用证据，核对差异。

CSV 表头可调整顺序，须包含全部十列。`cash_symbol`、`note`的内容可留空，其他字段必填。每批最多1,000笔、1 MB。

```csv
external_id,occurred_at,symbol,asset_type,action,quantity,price,fees,cash_symbol,note
平台A:确认单001,2026-09-03T10:00:00+08:00,000001,fund,buy,10,1,0.5,CNY,已核对确认单
```

- `external_id`：建议“平台名:确认单编号”，当前账户内唯一，最多128字。同一文件内重复编号拒绝导入。与已有记录查重不依赖录入来源；已有多个来源使用同一编号时需先人工核对。
- `occurred_at`：实际确认时间，必须含时区，毫秒最多3位；统一转为北京时间处理。按真实时间严格递增，同时发生但缺少顺序证据的成交阻断，不能导入未来成交或基线当日及之前的成交。
- `asset_type` / `action`：基金`fund`或股票`stock`；`buy`、`add`、`sell`、`reduce`。股票整股，买入或加仓为100股整数倍。
- `quantity` / `price` / `fees`：原始小数字符串；份额最多20位整数、8位小数，价格14位整数、6位小数，费用16位整数、4位小数。零费用明确填0；不接受科学计数法。数量与价格乘积必须精确落在成交金额存储范围内，超过8位小数时拒绝，避免隐含舍入。
- 查重比较代码、资产类型、动作、数量、价格、费用、实际时间和现金代码；备注不参与经济内容查重。内容一致标记为已入账，内容不一致整批阻断。全部已入账时不创建新成交；混合批次只回算新增成交。

持仓市值沿用账本成交快照日期，历史正式净值另按其估值日期列出；平台对账必须核对快照日期。分红、基金转换、公司行动及资金划转继续使用对应入口。本功能不推断缺失的确认价格、手续费或完整历史，也不改变策略准入和前向模拟天数。

## 实现与失败处理

新增`POST /api/v1/ledger/replay/batch-preview`，接收`trades`数组和公共`reason`；已有确认接口支持单笔与批次，已有预览表保存冻结计划，无新增迁移、无新增付费调用。批量成交继续由受控`ledger.replay`计算进程在临时分析库中按时间回放。

确认强制再次验证原始估值文件，绕过相同计算输入的结果复用。确认结果必须与冻结预览一致；账户锁内一次保存全部新成交、持仓、历史净值及逐笔审计，任一步骤失败全部回滚。重复确认返回相同成交编号列表；不同预览并发或来源变化由账户指纹阻断。

切换账号、隐藏或卸载页面清空草稿、回执与预览；修改依据作废旧预览，迟到响应不能恢复旧数据。上传、预览、确认和分页有操作互斥；确认框取消不会写入。入账后刷新交易概览及完整历史，并提供对账中心入口。
