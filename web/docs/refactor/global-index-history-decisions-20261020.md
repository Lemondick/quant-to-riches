## Task 1 裁决与代价

1. Python 和 .NET 读取同一份 `exchange_sessions.json`，日历仍读取同一份 `exchange_calendars.json`。没有在两种语言各自复制四套时刻。代价：更改时段资源需要重新构建两端，并通过共享边界样本。
2. 新增 HK/US/JP 的官方 2026 年日历；海外时段也仅声明已核验的 2026 年。缺失年份、市场、日历继续返回未知，不套用 CN。CN 保持现有通用时段与管理员导入年份兼容。代价：海外跨年前必须核验并更新下一年日历和半日市时段，单独导入假日不会自动认证未知年份的交易时段。
3. 现有日历管理 API 和修订机制不变，半日市规则独立版本化，不新增数据库迁移或管理表单。代价：临时提前收盘等时段变更目前需要更新共享资源；管理端只能导入全日休市，不能编辑半日市。
4. 不增加重复的行情时间字段。实际来源时间、抓取时间、日历修订仍沿用原契约；时段资源版本和官方证据保留在资源及本文。代价：API 消费者不能直接读取时段资源版本，运维需从对应发布代码查询。
5. 集合竞价数据能力未经核验时仍明确不可用；连续交易的旧观测在午休或闭市边界按本市场校验。美股 14:58 不再误触发 CN 的收盘集合竞价限制。
6. 旧“海外无内置日历”测试改用显式空日历或未配置的 2028 年。保留未知状态断言；已有真实 2026 年美股来源时钟的测试改为验证有效状态。没有删除失败分支或 PostgreSQL 集成覆盖。

Task 1 的实际 RED：共享 Python 4 个测试方法产生 34 项失败，原生共享测试 25 失败 / 2 通过。实现后共享及报价 Python 17 通过，原生相关 96 通过 / 3 个 PostgreSQL 用例因本机无实例跳过；这 3 项必须以 Linux CI 为准。Worker 日历相关 4 通过。全量本地首次运行发现上述旧测试前提后修正；不将其失败运行计为通过。后续 CI 结果单独追加。

## Task 2 历史源裁决与代价

1. 注册表 `2026-10-20.2` 分别声明 16 项历史映射，保留原四项 `legacy_history_symbol`。其余腾讯映射均从实际返回的 `qt` 代码、类型、名称及命名空间核验；历史不接受 `qfqday` 股票复权价格替代指数日线。北证50腾讯只有一条真实日线，改用独立核验的东方财富 `0.899050`，每次再次检查代码、名称、市场。币种未由腾讯/东方财富返回时仍注明注册定义及证券身份依据，不宣称供应商提供了币种字段。
2. 日经现货身份、JPY、OSA、东京时区以及 OHLC 已从 12:54 UTC 保存的 Yahoo 5 日实际响应独立核验。正式请求同端点的两年窗口，接收多少条就显示多少条，不承诺一定有两年历史。14:43 UTC 起本机较长窗口及后续 6 月、1 月请求出现读超时/TLS 连接错误，未禁用 TLS、未重复轰炸接口，也未把它记为实测长历史成功。代价：日经较长窗口当前可用性未确认；端点失败时返回真实失败，不能凭五条保存样本宣称当前有两年可用数据。
3. 日 OHLC 必须为正有限数、符合高低开收约束、日期严格递增且唯一，不含未来、周末或已核验的休市日。未知历史年份不套用当前年假日；没有补齐缺口或拼接另一来源的点位。
4. 腾讯美股请求 640 条实际会返回 641 条（含当天未完成日线）。先校验全部 641 条，最多发布最近 640 条，超界或被截掉的坏数据同样拒绝。上证收益实测仅 538 条，从其实际起始日显示，不填充成立前历史。
5. 所有来源暂不输出成交量。腾讯港股末列实测形似成交额，其他指数单位也未独立核验；Yahoo 指数 volume=0 不视为真实成交量证据。统一 `volume_status=omitted_unverified_unit`。代价：本阶段不会提供指数成交量柱，避免把金额、份额或占位零混用。
6. `source_time` 保留为日期型历史的空值，实际日记录日期用 `updated_at/trade_date`；`source_quote_time` 单独保存该响应的报价时钟，抓取时间不会充当报价时间。当天记录标记 `is_partial`，来源时钟未能确认已跨过本市场收盘上界时保守保留未完成标记（包括北证无时钟、港股随机收市窗口）。代价：已收盘但缺乏精确时钟证明的日线可能仍提示收盘未核验。
7. 各历史请求保留 PublicHttp 的并发、大小、无重定向、超时和失败熔断。正式 Worker 的稳定 `traced_get` 使用容量 4 的传输实例缓存，使熔断状态可跨任务保留；解析失败不会伪造数据或污染其他指数。
8. 浏览器历史测试改为显式注入未接入响应，继续覆盖空图和提示；正常日经映射则另外验证图表出现。没有因为注册表现在有 16 项历史映射而留下永远触发不到的旧 UI 测试。

实际验证：新历史测试先因缺少 `index_id` 参数产生 40 项错误（另一次从错误目录运行的 import 错误不算行为 RED）；实现后全量 Worker 146 通过，Python 注册表/报价/时段相关 23 通过，原生注册表/API 18 通过 / 1 个 PostgreSQL 跳过等待 Linux；六种宽度的连接模式浏览器通过。保存的实际响应经正式解析器全部通过：15 项各 538–640 条，日经保存样本 5 条；这是保存响应的重放校验，不冒充新的在线查询成功。首次 Worker 验证曾把传输封装错误预期成 OSError，改为原有 PublicHttpError 契约后重跑通过。源码与正式 HTTP 请求失败分别记录。
