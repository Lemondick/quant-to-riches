4. 不增加重复的行情时间字段。实际来源时间、抓取时间、日历修订仍沿用原契约；时段资源版本和官方证据保留在资源及本文。代价：API 消费者不能直接读取时段资源版本，运维需从对应发布代码查询。
5. 集合竞价数据能力未经核验时仍明确不可用；连续交易的旧观测在午休或闭市边界按本市场校验。美股 14:58 不再误触发 CN 的收盘集合竞价限制。

## Task 3 路由、刷新与真实源异常的裁决

1. 原生 API 的原四项保留原 `{symbol}` 缓存/任务输入；其余十二项使用 `{index_id}`，与 Worker 一并接通。新 ID 响应必须同时匹配 ID、代码、市场、币种、来源及来源代码；原四项只允许省略旧协议没有的字段，凡是已有字段冲突仍拒绝，不能重命名成所选指数。注册表现在没有未接入项，删除了循环零次的旧原生测试；未知 ID/冲突输入的零任务行为、浏览器显式未接入响应仍覆盖。
2. 每个市场独立判断交易窗口，包含本市场收盘后五分钟的收尾抓取；午休和官方休市不按连续交易采集。自动循环只要任一启用市场处于窗口就运行，不再被 A 股闭市阻止。`market_sessions` 和 `refresh_active_markets` 增量返回；旧 `market_session` 保持 CN 兼容语义。
3. 报价按供应商与市场分组，最多两组并发。活动窗口默认短 TTL 5 秒，休市默认 300 秒（构造配置独立，范围不超过 3600 秒）；活动/休市使用不同缓存键，开市不延用休市 TTL。代价：完整冷请求从两次变为四组请求，避免同一来源一个市场故障拖垮其余市场；页面检查、后台循环和供应商缓存仍是不同周期，不代表实时授权或延迟保证。
4. 主快照完成后，每轮最多轮换预热两项历史；常规循环只选活动市场，首次/手动刷新可从全清单轮换。报价、资讯、基金估值及资料继续有界排队。代价：首次闭市启动只预热两项，其他历史在用户选择时按既有准备流程入队；多个活动市场的历史更新时间取决于轮换及 Worker 负载，不承诺每条日线每 30 秒更新。
5. 后台辅助入队使用 18 项上限，账户既有上限仍为 20；同一事务检查，保留两个排队名额。领取时主行情快照优先于更早的辅助任务，保留全局最多三个运行任务。代价：已有较早辅助任务可能等到主快照完成；运行任务不抢占，用户已占满账户额度时仍遵守原上限，不宣称存在无限容量。
6. 历史持久缓存仍为 1 小时，API 内存保留缩为 60 秒，避免后台替换共享历史后继续读一小时旧图；前端缓存与常规检查为 60 秒，并保留原有有界旧快照快速复查。代价：休市历史的 API 内存命中寿命也较短，但持久资料和前端缓存仍可复用。没有改成展示请求等待远程采集。
7. 主行情的派生快照最多保留 14 天，用同一保留常量控制读取和清理，跨周末仍能展示原始观测。旧采集整体继续标为 stale，各项按自身市场重算，时间不更新成读取时间。代价：超过 14 天仍会明确不可用；这不是此前已移除的“基金净值统一 14 天过期”规则，也不改动财务数据或备份。
8. 日期型历史继续按本市场最新交易日判断，原生读取不把上游 invalid/unavailable 或未知质量值洗成 valid；缓存过期与历史末日落后使用不同原因。新增 API 内存与真实 PostgreSQL 测试覆盖旧四项复用、新十二项隔离、身份冲突、跨周末、保留期、美国开市而 CN 闭市、排队预留及优先领取。
9. 实测 Yahoo `1mo` 响应提供了真实 `regularMarketPrice`、来源时钟和上一交易日 close，但最新日线 close=null，其他开高低仍有值。报价可使用同来源的真实 metadata 点位及实际前收，仍检查已提供的当日 close 一致性；缺失前收、错误身份、非有限数仍拒绝。历史绝不以点位填空，只剔除来源时钟所属日、处于末行且字段不全的日线；已提供的值先通过数值及范围检查，发布 `omitted_incomplete_bars`、较早末日和 stale。代价：报价可正常显示而 K 线截至较早交易日，界面明确提示来源日线缺失；其他位置的坏行不因此被忽略。
10. 新 null 边界先 RED 后修复。真实 1 月响应重放得到 17 条完整日线、末日 2026-10-19、剔除 1 条不完整日线；随后正式两年请求实际取得 485 条完整记录（2024-10-21 至 2026-10-19），同样剔除最新 1 条并标 stale。取代 Task2 的“较长窗口尚未确认”限制，但不把单次成功视为持续可用。最新完整报价探测 15 项成功，日经该次读超时明确 unavailable；保留真实来源失败。另一次美股历史返回 HTML 被拒绝，也没有记成有效观测。
11. UI 仅增加本市场/币种、真实来源、未完成日线和缺失日线说明；不重做主题、导航或其他页面。不同 ID 的浏览器历史夹具现在使用不同 OHLC，并验证迟到响应后仍是当前 ID 的真实输入读数；同页面注册表版本变化会重新读图。由此补齐阶段 B 留下的两项浏览器覆盖缺口，不能倒称阶段 B 当时已覆盖。
12. 修正验证配置错误：最初三个旧脚本未指向本次构建，失败不算产品 RED；改用脚本实际支持的环境变量和绝对 build 路径后，88 项页面/宽度检查、32 项两卡片检查通过（拆分帧 0、位移 0）。K 线脚本又复现本次关闭旧快照快速复查导致的回归，恢复该流程后 8 组通过；冷准备约 1.37–1.44 秒，缓存重访约 47–68ms，均为合成夹具流程，不是生产接口速度。连接模式指数浏览器六种宽度、部分行情/错误身份/无历史/迟到/版本变化通过，Node55、类型、lint、格式及构建通过。
