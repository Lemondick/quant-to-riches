# 后台性能改造：本地落地与验收记录

日期：2026-10-17。此记录补充并更新此前的 `backend-performance-all-evidence-20261017.json`。本地实现与功能回归通过，严格性能目标尚未全部达标。

## 已落地

- P0：公开数据快照与缓存、常驻公开 Provider、禁用请求路径全历史净值爬虫。盘中失败时使用两条经过来源、日期及数值校验的本地官方净值；保留原观测时间及官方日涨幅。
- P1：高频鉴权、持仓、账本列表、历史、偏好、聚合及队列使用原生异步 I/O；DuckDB 只读连接分流；交易时段预热；PostgreSQL 通知替代 200ms 轮询。现有低频领域写入及 CLI 仍保留同步兼容入口。
- P2：11 个前端路由接真实账户和业务 API；SWR、单次概览聚合、会话及 CSRF 绑定、全链路追踪。轻量策略参数校验常驻执行，策略预览及财务/模型计算继续隔离。
- 继续优化：账户显示缓存合并并发读取，迁移 `0021_account_display_revision.sql` 保证提交后立即切换版本；批量用量计数移出 HTTP 关键路径；持续线程池采样；旧站回切导出兼容派生版本字段。

## 性能实测与未达项

纯内存读取为 0.0053ms/次；进程内信号发布至等待者恢复的 P95 为 0.009ms。持久化完成加网关再次读取为 24.239ms，两者不能混为同一测量。

缓存切页至真实账户行渲染后两帧约 79.3ms。空浏览器缓存、已有登录 Cookie 的冷首屏中位数 496.8ms，最大 808.1ms，未达到冷首屏 300ms。

以下为 50 并发、预热后 50 次请求的 P95，单位 ms；两种客户端驱动均保留，不能只选择较快的一组。

| API | Node fetch HTTP | 50 个复用连接 HTTP | fetch 服务端 gateway |
| --- | ---: | ---: | ---: |
| `/api/v1/market/snapshot` | 63.9 | 77.2 | 6.5 |
| `/api/v1/dashboard/summary` | 86.2 | 42.2 | 5.7 |
| `/api/v1/market/quotes?indices=000300` | 90.3 | 34.7 | 55.1 |
| `/api/v1/funds/valuations?symbols=510300` | 49.3 | 56.7 | 9.2 |
| `/api/v1/funds/510300/detail` | 60.9 | 66.5 | 20.0 |
| `/api/v1/market/news` | 76.0 | 120.5 | 11.7 |
| `/api/v1/portfolio` | 47.4 | 34.4 | 10.5 |

严格的全部 HTTP P95 <50ms 尚未满足。最近 10 秒线程池采样峰值为 49，负载结束待执行数为 0；不能据结束时为零宣称全程零排队。用量计数丢弃数为 0。

测试使用本机 `quant_perf_ui` 的明确合成夹具，仅有一个基金持仓及一个指数；Kestrel 直接提供正式构建资源，未包含 Caddy、HTTPS 和生产网络。夹具、测试账户和性能结果不能替代真实数据验收。
