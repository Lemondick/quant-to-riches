# 自定义基准与归因历史补全（2026-10-07）

本轮按现有功能继续查漏补缺，保持 C# / PostgreSQL 主后端、受控 Python worker 和 H5，不使用 Docker。仅使用本机隔离账户和合成行情，不调用 AI，不切换正式环境。

## 修复与补全

- 自定义基准此前只有保存接口、没有编辑页面。现在可在“持仓复盘→行业归因”或“策略→研究监控→组合基准”新建、编辑及设为默认。1至20个成分填写百分数，权重为正且合计100%；支持股票完整代码和现金 CASH。
- 前后端规范化成分代码的外部空白与大小写，将 CASH.CNY 归一为 CASH；拒绝规范化后的重复代码、内部空白、无效权重及控制字符。无效输入不覆盖已有基准或默认状态。自动归因接受与基准接口一致的128字符基准ID。
- 新增 `GET /api/v1/attribution/reports?limit=20&offset=0`，按当前账号、创建时间及ID倒序读取摘要。条数限定1至100，偏移限定0至100000，返回 `total`、`has_more`、`items`。计数和列表在同一读取事务中完成；摘要不加载来源大对象。
- 页面提供历史分页及完整报告读取，刷新后无需记住报告ID。尚未计算的兼容草稿显示状态；已完成报告可读取明细及来源。
- 增加“行业归因”模块导航。读取成功报告时清除先前的自动阻塞提示；未读取基准时明确提示读取或新建，避免误显示无配置。基准保存、历史读取和报告读取在切换账号或卸载后拒绝过期响应。
- 实际 H5 验收发现 UniApp 将普通 `<input type="checkbox">` 转换为文本控件，已使用原生动态 input 修复默认基准复选框及新表单输入控件。

修改基准只影响后续计算。已保存报告保留当时的基准、来源和结果；本轮没有改变交易、持仓、事件或审计事实。

## 仍未支持的范围

自动归因仍限定固定股票与现金、当前账号自定义固定成分基准及充分的历史来源证据。动态多期持仓、基金行业穿透和官方指数历史成分尚未实现，相关输入继续明确阻塞。本轮不替代正式环境切换、真实数据准入或长期负载观察；完整AI日报的待验收情况仍以迁移状态页为准。
