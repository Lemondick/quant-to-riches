## 功能与修复

用户填写兼容 API 地址和 Key，C# 读取 `/models` 并保存该账号的模型目录。资讯、策略和复核角色从此目录选择；Jev 使用既有独立连接。执行任务时冻结并使用该账号保存的选择，任务进行中禁止修改配置。Key 不返回明文，也不写入浏览器存储。

| 发现的问题 | 修复及验证 |
| --- | --- |
| 日报提示词要求引用不存在的输入字段，真实模型返回了错误的引用编号 | 提示词明确候选来自 `input.symbols`，引用逐字复制 `input.sources[].id`。保持引用校验，未知编号仍拒绝。两项回归通过；后续真实日报因连接超时失败，因此不能认定提示词修改已使完整日报成功。 |
| API 返回多个公开地址，部分地址 TCP 可连接但 TLS 握手超时 | C# 模型目录读取逐个尝试已验证地址，每次最多 5 秒，总期限 20 秒覆盖 DNS、连接和响应读取。权限错误及无效响应不继续换地址；调用方取消立即停止。 |
| Python 付费模型请求只尝试第一个地址 | 仅在发送 HTTP 前切换 TCP/TLS 地址，连接共享原有总期限；TLS 使用原主机名和证书校验，所有 DNS 地址先校验。HTTP 已提交后发生读取超时仍只发送一次请求。 |

连接诊断中，旧 C# 实现约 5 秒超时，而同一 API 和 Key 的独立模型目录请求返回 200、13 个模型。TLS 逐地址诊断确认部分地址握手超时，其他地址有效。

修复后原生目录读取返回 200，耗时约 6.8 秒。一次后续刷新仍因外部连接超时在 20 秒内返回 422，原配置没有变化；稍后的显式刷新返回 200，约 2.4 秒。地址切换不能保证外部服务始终可用，但失败有界且不覆盖已有连接。

Python 实际 TLS 检查在四个已验证地址中切换到可用地址，7.031 秒建立通过证书验证的连接；此检查未发送任何模型 POST，也没有生成费用记录。
