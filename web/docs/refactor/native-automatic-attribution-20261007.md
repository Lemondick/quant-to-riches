# 自动行业归因实现与验收（2026-10-07）

后续已补齐自定义基准配置页面和归因历史列表，当前发布包及最新回归见 [基准与归因历史补全](native-benchmark-history-20261007.md)。下文保留自动归因首轮实现和验收记录。

已接通股票与现金固定持仓的自动行业归因，保留手工行业输入。保持 C# / PostgreSQL 主后端、受控 Python worker 和 H5，无 Docker。本轮不调用 AI，不改交易与持仓。

## 当前行为

`POST /api/v1/attribution/reports/automatic` 接收组合名称、当前账号的自定义基准 ID、起止日期。读取唯一已确认基线及 `portfolio_account_import` 原始持仓审计，使用原始数量和期初收盘价格计算金额，再按历史行业汇总；不会把当前持仓回填成历史持仓。

首版仅支持基线之后至结束日期没有交易、分红、公司行动、冲正、资金流、校准、待确认事件或手工持仓覆盖的固定股票/现金组合。基准使用已保存的固定成分及权重。现金收益为零，股票收益为结束价格 / 开始价格 − 1；属于价格收益研究模型，不包含分红、税费或动态再平衡。

行业分类必须有期初或更早的记录；同日有效分类冲突会阻止计算。联调发现账户标的行业为空时误挡历史分类，已修复并加入回归。所选两天都必须有准确日期的已验证收盘价格，不采用上一日收盘或盘中估值。

worker 校验账号目录、价格文件内容哈希、行数、准确日期及缓存价格一致性，记录行业缓存和价格文件指纹。C# 使用十进制金额汇总行业、计算 Brinson–Fachler 三项效应，并在账号写事务中重验账本、基准、快照元数据及文件指纹。Windows 文件读取句柄保持到提交结束；缺证据不建空报告，计算期间状态或文件变化返回 409。每次申请报告都会重新读取文件证据，不复用先前完成的计算结果。

迁移 `0013_attribution_sources.sql` 为报告增加 `data_source`、`source_json`。自动报告来源为 `native_static_price`，保存基线、标的输入、基准定义、价格快照和指纹摘要；公开结果不包含私有文件路径。报告及明细一起保存。手动重算后来源改为 `manual_sector_input`，清除自动来源信息。

页面入口在“我的持仓”下方的 Brinson 归因分析：填写起止日期，读取账号自定义基准，选择后点击“自动生成并保存报告”。缺项直接显示原因；成功后显示来源、报告 ID、行业效应和模型限制，支持重读。切换账号和离开页面会清理选择、结果并忽略迟到响应。

## 后续边界

动态交易组合多期归因、基金行业穿透、官方指数历史成分及分红/税费总收益仍未实现，当前接口缺少相应证据时会阻止生成。

正式服务器、正式 CA、真实冻结账本、异机密钥恢复及 24–72 小时运行观察仍待对应环境。完整四角色日报和生产研究准入的边界沿用 [迁移状态](native-migration-progress.md)。本轮未提交、推送或切换正式服务器。

验收结束后关闭本轮隔离 API、三个 worker、监督进程及 PostgreSQL，发布包和合成数据保留。
