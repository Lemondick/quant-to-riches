# 导入回执恢复、金额精度与键盘确认修复（2026-10-08）

本轮完善三个实际使用问题：已入账的成交导入回执离开页面后无法找回；财务小数字符串转换为浮点数后可能改变金额；Enter打开确认框时可能被框架同时当作确认。继续使用本机隔离环境，无Docker，无正式环境切换。

## 使用与行为

在“交易账本→成交导入→已保存的成交导入回执”按时间分页查看过去批次，点击“查看回执”核对原CSV行号、成交编号、新增/已有跳过结果及账本记录编号。可以再次下载整批回执，导出包含批次、入账时间及核对依据。刷新或重新登录后仍可读取；账户切换、页面隐藏和卸载清空本地结果，迟到响应不能恢复旧账户内容。

回执使用入账时冻结的计划和确认编号，不受预览15分钟有效期影响，不重新计算或重复入账。后续更正应同时查阅账本审计，回执代表导入当时的结果。未确认预览、单笔补录和其他账户的批次不能通过回执接口读取；未登录返回401，非当前账户的回执返回404。历史列表只读摘要，按需读取逐笔结果，无新增数据库迁移。

共享金额格式化按十进制字符串计算，保持大整数、小数、进位和负数精度。首页持仓单项保留原始市值，首页及持仓页的资产、现金和截图持仓总额先精确求和再舍入，缺少金额时保持未知。例如`9007199254740993.12345678`显示为`¥9007199254740993.12`，不会变成`¥9007199254740994.00`；再加入现金`0.87654322`和股票市值`0.01`，总额显示`¥9007199254740994.01`。两个`0.004`先相加，显示`¥0.01`。

金额显示按分四舍五入，半分远离零舍入；小于半分的正负数均显示零。存储和CSV保留原有精度，走势图占比及原本以浮点数计算的收益估算仍使用原算法。

成交导入、历史补录、净值入账和回放归档删除改为在按键释放时打开确认框，并阻止该事件传播到框架的全局确认监听。首次Enter或空格仅打开确认框；需要另一次明确确认才能提交，取消保持原记录。鼠标流程保留。
