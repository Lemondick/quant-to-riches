# 多期归因与模型用量优化验收

日期：2026-10-07。已完成连续单期归因报告的多期连结，以及原生 worker 的服务商用量字段兼容修复。验收使用本机隔离 PostgreSQL、合成账户及原生发布包，部署方式保持单服务器运行。

## 多期归因功能

从“持有→快照资产→行业归因”读取报告历史，可跨页选择2至60份已完成单期报告。报告须属于当前账户、使用同一组合与基准，前一期结束日期等于下一期开始日期。服务端按时间排序，允许各期采用不同权重，并拒绝重复、缺期、重叠、草稿、嵌套多期和不完整证据。

使用 [Frongello 递推](https://github.com/R-Finance/PortfolioAttribution/blob/master/R/Frongello.R) 连结行业配置、选择与交叉效应。组合和基准收益分别复利累计，总效应对齐累计超额收益；每期效应重新计算并核对原汇总，数值超出精确计算范围时拒绝保存。行业后续消失时仍保留其此前效应，完全亏损和零超额收益也有明确结果。

保存时冻结所选报告的行业输入、原始基线、行情快照和来源限制。累计行业效应单独存储，不虚构整个区间的单一期初权重。原报告修改不会改变已保存的多期证据；旧单期重新计算接口对多期报告返回409，调整来源后需要生成新报告。

写入按账户事务执行，并锁定来源报告；重复提交相同报告编号与来源只返回同一份报告，编号冲突返回409。页面在响应丢失后复用编号重试，切换账户立即清空选择和结果，迟到响应不能恢复旧账户内容。新增0014迁移扩展报告来源约束，既有0013保持不变。

这项功能连结已保存证据，各期可采用不同权重。它尚不从成交自动重建各期持仓和收益，不自动中和外部资金流，也不补全基金全仓或官方指数历史成分；单期原来源的限制继续有效。

## 模型用量采集

原生 worker 统一使用已有用量校验入口，支持 `prompt_tokens/completion_tokens` 与 `input_tokens/output_tokens`。两组同时出现时必须一致；布尔、负值、越界、缺项及不一致的 `total_tokens` 保持未知，避免错误核算费用。字段含义参考 [官方 Token 用量说明](https://developers.openai.com/api/docs/guides/token-counting)。

已验证零用量费用为0；输入123、输出45，单价分别为每百万1和2时费用精确为0.000213。缺失单价仍为未知费用，已知部分保持不变；金额预算继续阻止费用不确定的后续调用。旧未知费用不补估，失败或中断的未确认用量继续按未知处理。

本轮没有调用外部AI或OCR服务，修复的是采集和核算路径。四角色完整日报与服务商实际账单对账仍需单独验收。
