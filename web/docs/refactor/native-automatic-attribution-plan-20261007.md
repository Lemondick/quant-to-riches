# 自动行业归因实施范围

沿用当前 C# / PostgreSQL、受控 Python worker 和 H5 流程，直接实施并验证，不增加审批环节或 Docker。

## 数据和行为

- 读取当前账号唯一已确认基线的完整原始持仓审计；不拿当前持仓代替期初持仓。
- 首版支持基线之后未发生交易、资金流、分红、公司行动或校准的固定股票/现金组合，以及账号已保存的自定义股票/现金成分基准。其他情况返回具体缺项，避免把静态模型当成动态持仓归因。
- 使用所选两天的已验证价格快照、期初或更早的行业分类。对每份价格文件核对账号目录、内容哈希、行数和精确日期；不得用前一天或盘中估值替代。
- 自动从标的期初金额计算行业权重、行业价格收益，然后调用 C# Brinson–Fachler 计算。现金收益按零处理；明确标注“固定持仓价格收益，不含分红和税费”。不推断指数历史成分，也不进行基金穿透。
- 计算后再次核对账本/基准/行情元数据和文件指纹；创建完整报告及保存来源在同一事务完成。缺证据不创建空报告。
- 保存标的输入、基线、基准定义及行情证据摘要。手动重算自动报告时改标为手工来源，清除自动证据，避免来源错标。
- 前端读取账号基准，选择基准与日期后一键自动生成；显示缺项或已保存报告，切换账号清掉选择与结果。

## 验收

先运行失败用例；再实现原生计算操作、API 和页面。验证多个标的行业汇总、权重/超额收益恒等式、缺少基线/历史行业/准确价格、文件篡改、期间活动、跨账号、并发数据变化及持久化。运行 C# 和 Python/worker 全量回归、实际 Vue 交互、类型/lint/格式/构建，再打包并在本机 HTTPS API 与三个 worker 验收。

本轮无需真实 AI 请求。自动获取官方指数历史成分、动态持仓多期归因及基金穿透不属于这一数据模型。
