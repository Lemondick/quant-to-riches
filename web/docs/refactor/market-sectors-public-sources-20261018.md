# 市场行情公开数据口径与验证

用户于 2026-10-18 选择：先完善公开数据源，并如实标明延迟。此版本没有接入付费或交易所直连行情，也没有推定与养基宝使用相同数据商。

## 来源与目录

东方财富目录取自官网 `https://quote.eastmoney.com/center/api/sidemenu_new.json`，按 `type` 区分行业、概念、地域。行业包含一、二、三级。板块代码与名称必须同官网目录一致。行情列表沿用当前官网的公开筛选参数，按代码排序分页；核对总数、重复页、缺页后才使用该类报价。目录中没有取得报价的板块仍可搜索，涨跌幅为空，不能补成 0。官网配置与本轮原始公开响应已保存到本地 output/market-v17 供核查。

新浪分别读取 newSinaHy（新浪行业）、newFLJK 的 class（概念）和 area（地域），完整解析响应字典。涨跌幅、成交额直接来自源字段，不用股票名单自行估算。新浪的板块平均涨跌与东方财富板块指数涨跌口径不同，两套目录独立展示，不能拼成同一排名，也不能把两源记录数相加当作唯一板块数。

## 时间、缺项与刷新

- `observed_at` 是源提供的行情时间。东方财富使用 f124；新浪这些接口不提供该时间，固定为空，显示“来源未提供 / 延迟未知”。响应 Date、抓取时间不能代替行情时间。
- 板块 `fetched_at` 是这一轮采集的开始时间，页面标作“抓取”。根快照 observed_at 是组合快照采集时间，不是各行情的时间。
- `sector_catalogs.complete` 表示目录完整，不能解释为全部报价可用。`received` 包括无报价的目录项，`unquoted` 给出其中无报价数量；逐项空值保持空值。目录完整但报价失败时，页面明确显示“目录已核对 / 行情源暂不可用”。
- 源失败可读取七天内同数据商、同分类的原始缓存，保留原时间并标记 stale / error。未取得过有效报价时，只保留可核对的目录名称，不编造涨跌幅、成交额或行情时间。
- 交易日由现有交易日历确认；按北京时间显示交易、午休、休市或未知。后台交易时段以 30 秒为目标调度采集，浏览器可见时每 15 秒检查快照；隐藏时暂停，返回时检查，离开页面清理定时器。请求与外源延迟可能延长一轮采集，不能据此承诺秒级行情。
- 手动刷新使用 refresh=true 触发后台新采集，HTTP 先返回现有有效快照，不在 HTTP 请求中等待外源。跨客户端最多每 30 秒接受一次显式刷新请求。

## 兼容及性能

新版页面请求 `/api/v1/market/snapshot?fullCatalog=true`，包含分类、来源、完整目录与可空报价。未带此参数的旧页面只收到一个数据源的有效行业报价，避免旧脚本的 Number(null) 生成假零；真实 0% 保留。账户总览只取指数分区，避免附带整份板块表。

板块表先搜索和排序整个分类，再每页显示 50 条。小屏取消这张表的名称固定列，避免名称列覆盖整个可视区域。现有主题、K 线和右侧卡片布局沿用。

## 验证边界与回退

发布证据见同目录 market-sectors-live-evidence-20261018.json。真实接口使用临时只读验收会话，检查后撤销；浏览器布局测试拦截账户请求，并重放保存的真实公开板块和历史记录，不把夹具当作线上账户或行情证据。新浪全部报价逐条与独立读取的原始字段核对，证明归一化一致；不声称已验证盘中逐笔行情。2026-10-18 是休市日。

没有数据库结构迁移。升级前备份及财务指纹保存在发布证据中。若紧急回退至 v16 或更早的 UI / API，应持有备份锁、确认队列空闲、停止四项服务、恢复相应主链接及 UI 配置，并仅清理这次带 sector_catalogs 的公开 market.snapshot 缓存，再让旧 Worker 重新采集。不可把带空报价的新快照交给旧脚本，也不要删除账户或财务表。单纯切换到过渡版 v17 不能修复其旧客户端空值兼容问题；优先保留最终兼容补丁版本。
