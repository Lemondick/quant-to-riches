# AI 预检、基金执行回放及自动验收

目标：用户在调用付费模型前看见缺项和处理入口；已核对的基金订单证据可通过原生 API 和页面回放、留档、导出；新增功能进入 CI。

范围及验收标准：

- [x] 预检复用报告证据规则，不调用模型、不占报告额度，不读取或传递模型密钥。缺项提供实际页面入口，账户切换与离开页面清空预检；生成仍由服务端校验配置、额度、预算。
- [x] 接通已有基金执行引擎。证据包有大小、条数、时间和格式限制；按公布、确认、到账时间回放，未结清和拒单不输出净收益。归档属于当前账户，冻结输入和结果、校验指纹并可导出。研究回放不自动取得策略准入资格。
- [x] CI 包含之前遗漏的优化脚本及新增功能验收。真实 Chromium 验证预检缺项、显式生成及账户切换；边界服务使用合成响应，禁止外部模型请求。
- [x] 本机隔离执行 C#、Python、worker、前端与浏览器验收，记录结果；不正式切换，不启动长期后台测试。

实现顺序：先写行为测试并观察失败，再实现原生路由及 worker 操作；随后页面、CI 和浏览器验证，最后补齐文档。

执行记录：

- 沿用当前工作区和既有修改。用户已授权继续直接优化；不额外要求设计确认，不提交、推送或启动 review。
- 基金闭环本轮指证据包→执行回放→归档→导出。真实交易与 AI 报告的逐笔关联尚无数据协议，不能把回放假定为实际账户业绩，也不能解除现有策略证据门槛。
- 预检和生成都消费当前账户快照与同一证据规则。预检为提示，不是生成授权令牌；生成时重新冻结输入。

完成记录：C#159、Python420、worker46、原生工具8、10组前端脚本及7个真实Chromium场景通过。原生HTTPS链路和页面导出通过；模型调用数与报告数不变，8张财务事实表指纹及原隔离数据库保持。最终发布包345个文件指纹核对通过。

页面验收发现并修复了UniApp按钮禁用状态的ARIA表达和归档北京时间显示；新用例观察失败后通过。当前发布包为release-preflight-replay-final-20261008，初轮发布包仅为过程产物。
