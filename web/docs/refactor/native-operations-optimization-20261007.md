# 运行稳定性优化与隔离验收（2026-10-07）

本轮落实建议中优先级最高的运行恢复、运维监测和跨年交易日历管理。沿用单台服务器、个人或几十人使用、原生发布和本机隔离验收的目标，不使用 Docker。验收全部使用合成账户及独立 PostgreSQL，没有切换正式站点，也没有新增 AI 或 OCR 调用。

成功标准是：后台能识别执行器不足、队列积压、磁盘和备份异常；日历管理能读取、校验、保存并阻止并发覆盖；正在正常提供服务的站点能完成定时停服备份后恢复；归档能在新空库和新目录实际恢复，保留财务事实与有效证据。

## 完成的优化

### 运维监测

- 管理后台显示有效 worker 数量与期望数量。只有30秒内、未停止的心跳计入；配置 worker 后，`/readyz` 要求达到期望数量，避免只存活一个进程就报告完整就绪。
- 展示排队、运行、超期任务、最早排队时间、站点与备份盘空间、最近有效归档年龄、自动备份结果，以及请求数、5xx数、平均响应时间和内存。
- 缺少 worker、等待过长、任务超期、磁盘不足、备份缺失或过旧、备份自动化失败、日历缺失均生成可见提醒。业务准入和运行告警分别展示。
- 默认阈值：队列等待120秒、磁盘可用比例10%、有效归档年龄36小时。Windows 启动器依据 `-Workers` 设置期望数量，Linux 环境示例须与实际服务数量一致。
- 归档年龄读取清单的创建时间，复制旧归档不能刷新年龄。最近10份归档的完整性校验使用60秒有界缓存，文件或恢复证明变化会失效。
- 请求统计包含健康检查。启动探测期间的预期503会计入5xx；本轮没有把这些数字解释为业务500错误。

### 年度交易日历

- 新管理面板支持按年份读取与保存官方公告地址及休市日期，显示当前与次年配置状态；10月起提醒准备次年日历。
- 只允许三家交易所官方 HTTPS 地址；校验真实日期和所属年份，重复日期去重排序。周末继续自动休市。
- 页面携带读取版本保存，后台按年份串行处理写入；旧版本返回409且页面保留草稿，需重新读取核对。
- 删除旧的无版本日历表单，避免两个入口行为不一致。切换账户或卸载使在途响应失效，按钮和输入支持键盘操作。
- 缺失日历继续阻止该年份的自动报告，没有凭空补齐2027年。验收中的2027年单日配置及2099年日期均为合成数据，测试修改后已还原，不可用作正式日历。

### Windows 定时备份与恢复

- 原生 supervisor 可显式配置每日备份时间、保留数量与超时。到时先检查计算任务和费用预留，忙碌或数据库不可读时延后60秒。
- 空闲后停止自身拥有的 API 和 worker，调用完整站点归档工具；新归档完全校验成功后才清理超额旧归档。
- 备份成功或失败均恢复所属服务，并等待配置数量的 worker 就绪。恢复失败则 supervisor 退出，由正式部署的进程管理器承担重启。
- 状态文件原子写入，同一天不会因重启重复尝试失败备份。中断遗留的 `running` 状态标为失败；损坏或不可写状态不会导致现有服务停机。
- 归档子进程固定使用 UTF-8，修复 Windows 旧控制台编码导致中文备份路径无法解析的问题。超时清理该归档工具及其 PostgreSQL 子进程。
- 实际恢复发现用户根目录快照无法重定位，已修复账户命名空间匹配。仍拒绝缺失证据、跨账户文件和仅凭同名文件猜测的替代，不改写快照的业务内容哈希。
- 恢复证明绑定归档哈希；管理后台区分归档完整性通过和实际恢复已验证。

Linux 保留手工停服归档及 systemd 运维流程；本轮没有接入或现场验证 Linux 定时维护。Windows 开机启动与崩溃重启也没有安装到本机系统任务中。
