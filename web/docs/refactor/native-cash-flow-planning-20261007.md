# 资金计划补全与隔离验收（2026-10-07）

本轮继续按现有功能查漏补缺，保持 C# / ASP.NET Core、PostgreSQL 和原生发布方式，不使用 Docker。仅操作本机隔离账号和合成数据，没有调用 AI、OCR 或切换正式环境。

## 补全的功能

- 在“持有→快照资产→资金计划”新增入口及模块导航，支持创建、读取、编辑、暂停、恢复和完成计划。方向为存入或提取；频率支持单次、每周、每月、每季度、每年。
- 提供指定日期的资金安排查询。仅生效且处于日期范围内的计划参与查询；改日期或修改计划后清除旧查询结果。
- 金额通过十进制文本传输，不经过 JavaScript 浮点转换；大于0、整数最多20位、小数最多8位。名称、日期、结束范围和备注由服务端再次校验，缺少起始日期直接拒绝。
- 新增 `PUT /api/v1/planning/cash-flows/{plan_id}` 和 `PATCH /api/v1/planning/cash-flows/{plan_id}/status`。编辑和状态修改必须携带读取时的 `expected_updated_at`；旧版本返回409，外账号返回404。并发修改只允许一个成功。
- 网页为创建请求生成稳定计划编号，内容相同的失败重试复用编号。服务端对同一编号和相同字段返回已有计划；字段不一致返回409，不覆盖已有记录或重复插入。
- 切换账号、连接或卸载时清空计划、查询结果和表单，使在途响应失效；失败编辑保留输入，方便重新读取后核对。
- 所有操作按钮支持 Enter、空格和辅助技术识别；完成提示使用“计划已完成”。

资金计划只是安排，不自动入账、转账或交易。真实到账后仍由用户通过账本确认；本轮不改变持仓、交易、事件或审计事实。

## 修复的缺陷

原创建接口在写库后计算 `start_date + 365天`。最大年份日期会在提交后报错，造成“提示失败但记录已写入”，并阻塞列表读取。现已限制预览范围并在事务返回前计算安全预览；9999-12-31创建、读取和查询均可完成。

排期始终以起始日为锚点：1月31日的月计划依次为1月31日、2月28日、3月31日；2024年2月29日的年计划在非闰年为2月28日，在2028年回到2月29日，不逐次累积日期偏移。

指定日期查询此前在判断是否到期前截取500条，可能被早期单次计划占满并漏掉后面的应执行计划。现移除该截断，回归覆盖500条早期非到期计划之后的有效安排。

## 使用边界

网页按起始日期展示前500条计划；指定日期查询不会因该展示限制而截断。预览列出起始日起365天内的前12次，便于核对排期，不表示从今天开始的下一批安排。无结束日期不表示无限预览。

本轮不增加自动记账、外部到账通知或自动转账。动态多期归因、基金穿透、官方指数历史成分，以及完整AI日报、正式环境迁移和长期负载验收的待办仍见 [迁移状态](native-migration-progress.md)。
