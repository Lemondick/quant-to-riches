## 稳定性与故障

- **20 账户并发读取，持续 920.47 秒**：19662 次请求全部 200，错误 0，P50 15 ms，P95 16 ms，最大 672 ms。负载为核心读接口，不代表 20 个模型任务并发，也不代表已经完成 24–72 小时持续运行验收。
- 强制结束一个归本轮所有的 worker：监督进程退出 1，API 与其他 worker 全部停止，监听端口和残留服务均为 0；完整重启后财务状态不变。
- 停止本轮独立 PostgreSQL：`healthz`、`readyz`、持仓接口均返回 503，耗时约 0.02 / 2.00 / 2.06 秒。重启数据库后同一会话恢复，ready 恢复约 0.28 秒，财务状态完全一致。
- 最终恢复环境由同一原生监督入口启动，三个 worker 提交新心跳；真实研究曲线和解释计算通过。Windows 服务级自动重启仍应由正式部署的外部服务管理器负责，不能把进程树清理误称为自动重启。
