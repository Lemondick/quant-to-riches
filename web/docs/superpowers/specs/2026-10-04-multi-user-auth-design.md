# 多用户登录与管理者后台设计

日期：2026-10-04（北京时间）

## 1. 已确认的需求与验收目标

为现有 Vue 3 / Uni-App H5 + FastAPI 网页项目添加账号密码认证。用户独立注册、独立使用，注册账号总数最多 30 人，没有注册截止时间。管理员计入 30 人。

现有账户数据只归本机初始化的管理员；其他用户从空账户开始。管理员后台显示用户名、注册时间、最近登录、账号状态，以及持仓、账本和报告数量。根据用户随后明确提出的详细使用情况需求，管理员可以只读查看用户持仓、账本、自选、报告正文和研究任务；不返回密码、会话或模型密钥。

必须通过以下验收：

1. 注册、登录、退出、修改密码可用；匿名用户无法调用业务接口。
2. 同时注册时账号总数仍不超过 30；重复用户名、失败注册不消耗名额。
3. 用户 A 无法读取或修改用户 B 的持仓、账本、自选、配置、截图导入会话、报告或后台任务。
4. 已有持仓、账本、偏好和私有模型配置仍由管理员使用，新用户不会继承这些内容。
5. 管理员能查看注册名额和所有用户的账号、使用概况；普通用户请求后台接口返回 403。
6. 退出、登录过期、密码修改后旧会话失效；切换用户不会显示上一用户的浏览器缓存。
7. 原有网页构建、源码检查通过；验证过程不执行真实交易或付费模型调用。

## 2. 方案选择与范围

采用统一账号库 + 每用户独立数据目录和 DuckDB。现有服务以单账户数据库和目录为依赖，复用这条边界可以覆盖现有业务接口而不逐表修改业务模型。

备选方案是在共享数据库的所有业务表增加用户字段并逐接口过滤。这需要同步修改账本、研究、文件配置和后台任务，遗漏过滤条件会造成越权，当前不采用。

保留现有 MVC 加业务服务层结构。新增认证仓库、账号服务、用户服务实例管理、认证控制器、管理后台控制器及对应网页页面，只修改必要的组装、启动和数据访问入口。

本次后台提供读取概况和详细使用记录功能，不增加账号删除、角色授予、管理员代登录或在线重置别人密码。账号恢复通过本机交互维护入口完成。30 人是累计注册账号上限，停用账号仍占名额。

## 3. 账号、会话与权限

### 3.1 账号库

使用 Python 标准库 SQLite 持久化账号与会话，放在 `data/auth/` 私有目录，不进入 Git、前端构建或静态资源目录。用户 ID 由后端生成 UUID，不以用户名组成文件路径。

用户记录包含 ID、唯一的规范化用户名、密码哈希、角色、账号状态、注册时间和最近成功登录时间。会话记录包含随机令牌的摘要、用户 ID、创建和过期时间、CSRF 校验数据。公开结果不返回密码哈希、会话令牌摘要、内部路径或密钥。

用户名采用明确的长度和字符限制，忽略首尾空格并统一大小写后查重。密码允许 Unicode，长度 15 至 128 字符，不去除密码中的空格，不保存或记录明文。使用 Argon2id（内存至少 19 MiB、迭代至少 2、并行度 1）进行密码哈希。

注册以 SQLite 写事务执行最终用户名查重、人数检查和插入。名额检查与插入属于同一事务，数据库同时约束用户名唯一。密码计算不持有长时间写锁；最终名额检查在插入时重新执行。数据库故障时拒绝注册，不回退为内存账号库。

### 3.2 管理员初始化

管理员通过本机交互维护入口创建，密码由操作者交互输入。公开注册不能创建管理员或领取已有数据；没有预置用户名密码。初始化完成之前，公开注册保持关闭。

管理员与原 `data/` 账户目录建立显式对应关系，原数据不自动移动、不复制给其他用户。后续用户只对应 `data/users/<user-id>/`。初始化重复执行不得创建第二个管理员或替换已有归属。

提供本机密码恢复入口，使用交互输入，并撤销该账号全部旧会话。用户名、角色、数据目录关系不由公开注册参数决定。

### 3.3 会话认证

登录成功后生成高熵随机会话 ID，服务端只保存其摘要。浏览器通过 HttpOnly、SameSite Cookie 携带会话；HTTPS 部署启用 Secure，本机 HTTP 调试只允许回环地址。会话最长有效期为 12 小时，服务器时间控制到期。

写请求执行 Origin 校验，并对已经登录的操作校验 CSRF 令牌。认证相关跨域请求仅允许精确配置的来源；不得使用允许凭据的通配 CORS。

登录错误统一提示账号或密码错误，并使用失败限流和不存在账号的占位哈希校验。注册与登录在后端单独限流。修改密码要求当前密码并撤销该用户所有会话，页面重新登录；退出删除服务端会话并清除 Cookie。

角色检查发生在后端。普通用户只能取得自己的业务上下文，管理员后台有独立权限检查。旧的全局 Bearer Token 不得在多人网页入口中替代用户会话、选择任意用户或授予管理员权限。

## 4. 用户数据和任务隔离

登录会话确定用户 ID，后端据此选择该用户的服务实例与内部业务应用。前端不能通过参数、请求头、文件路径或业务对象 ID选择其他用户的数据目录。

服务实例管理器保证每个用户只创建一套业务服务及一条对应数据库连接，使用锁避免并发首次访问重复初始化。接口仍复用现有路由和服务对象，不通过修改进程级环境变量切换用户。

每个用户独立保存：数据库、偏好、自选、策略配置、模型连接和 Key 文件、研究证据、截图导入临时会话、成本研究存档、报告、通知及任务状态。公共行情可以通过现有提供者取得，但不得继承管理员的账户事实或私有文件。

现有 `MarketAdvisorService` 默认从全局文件读取配置，需要允许服务组装显式注入用户配置。管理员保留原私有配置；其他用户默认无管理员模型 Key，通过自己的设置页面保存连接。TradingAgents 任务及交换目录同样按用户归属组装，不能共享可写任务目录。

系统启动和关闭统一管理已注册用户的调度器、研究服务和数据库连接，恢复时仍按用户归属处理已有任务，沿用现有任务重复保护。任务携带创建时冻结的用户服务上下文，不随浏览器用户切换。后台概况读取不触发研究、行情采集或模型执行。

所有可联网 HTTP 启动入口接入认证网关，包括本机完整网页、单独 API 和 Docker 生产入口。业务应用工厂可保留为网关内部实现，不能由旧启动路径暴露未认证的已有数据。健康探针和登录所需静态资源公开，业务接口和管理接口必须认证。

## 5. API 与错误行为

新增以下接口，路径统一位于现有 `/api/v1` 下：

| 接口 | 权限 | 行为 |
| --- | --- | --- |
| `GET /auth/status` | 公开 | 返回认证模式、注册是否开放、30 人上限和剩余名额，不返回用户清单 |
| `POST /auth/register` | 公开 | 创建普通用户，满额返回 409，成功后引导登录 |
| `POST /auth/login` | 公开 | 验证账号密码，设置会话 Cookie |
| `GET /auth/session` | 已登录 | 返回当前用户的非敏感账号信息及写请求所需 CSRF 校验数据 |
| `POST /auth/logout` | 已登录 | 撤销当前会话，清除 Cookie |
| `POST /auth/password` | 已登录 | 验证当前密码、保存新密码、撤销全部会话 |
| `GET /admin/users` | 管理员 | 返回名额统计和用户概况列表，支持用户名筛选 |
| `GET /admin/users/{user_id}/details` | 管理员 | 按分类分页只读查询持仓、账本、自选、报告记录和研究任务 |
| `GET /admin/users/{user_id}/reports/{source}/{report_id}` | 管理员 | 只读查询指定用户已保存的历史报告正文 |

保留业务接口路径，认证完成后转交当前用户的内部业务应用。未知或过期会话返回 401，普通用户访问管理员接口返回 403，名额已满或用户名冲突返回 409，参数无效返回 422，认证请求过频返回 429。

沿用统一的错误码、非敏感中文提示、请求 ID和响应安全头。认证数据库或用户数据库不可用时返回明确的不可用结果，不能读取其他用户目录作为回退。

## 6. 管理者后台

后台使用现有深色网页样式，适配桌面和手机。管理员登录后可从设置页进入独立后台页面，普通用户不显示入口。

页首显示注册总数、30 人上限、剩余名额和启用账号数量。用户列表显示用户名、角色、注册时间、最近成功登录、账号状态、持仓数量、账本记录数量和报告数量。

数量定义如下，页面同时标注这些口径：

- 持仓数：主账本与有效账户快照中，份额大于零的非现金标的去重后的数量，同一标的跨账户只计一次。
- 账本记录数：交易记录加分红记录的总数，包含保留在历史账本中的已冲正记录，不受页面分页限制。
- 报告数：AI 日报记录总数，加上已经保存报告正文的 TradingAgents 研究尝试数；同一任务不同尝试分别计数，没有生成报告的研究尝试不计数。

最近登录表示成功登录时间，不表示用户当前在线。接口和界面使用北京时间格式化日期，存储使用带时区的时间或 UTC 时间戳。

后台汇总使用明确的只读计数方法。尚未使用的用户显示零和未初始化状态；读取失败显示暂不可用，不用零掩盖错误。用户行增加“查看详情”：展示持仓数量、成本、市值、浮动盈亏及账户来源和数据日期；账本交易、分红与冲正状态；自选、历史报告正文和研究任务状态。主账本和平台快照分别汇总，避免重复相加。缺失成本不推算盈亏。

后台详情只查询可信账户对应的现有数据库与偏好，不初始化业务服务、创建用户目录、采集行情、执行模型或更新报告。正文只读取保存的report_json，不读取输入快照或私有模型配置。所有详情接口先校验管理员权限，再查找目标账号；账户之间的报告标识不构成访问凭证。响应不得包含模型Key、密码、会话或用户目录路径，浏览器详情只保存在当前页面内存中，切换账号、离开页面和迟到响应必须清除或忽略。

## 7. 网页登录流程和缓存

新增登录、注册和管理员后台页面，在设置页增加当前账号、修改密码和退出入口。注册页明确最多 30 人；名额满后关闭提交按钮，同时由后端最终控制。

应用启动及业务导航检查会话。未登录或会话失效时进入登录页，避免持仓缓存短暂闪现。直接打开业务页面地址也执行同样检查，后端持续保证匿名请求被拒绝。

网页认证请求使用当前服务的同源路径；开发环境通过 Vite 代理连接后端，生产通过现有 Caddy 代理。原服务连接逻辑按必要范围适配多人会话，页面不再要求用户手工填写共享 Bearer Token。

缓存键包含用户 ID 和登录代次。退出、会话过期和账号切换清理旧用户缓存、研究会话引用和界面状态；已经发出的旧响应因作用域变化而被忽略。会话令牌不存入 localStorage，CSRF 校验数据保存在当前会话内存中。

## 8. 启动、部署和维护

保留 `启动网页版.ps1` 和 `web/start.ps1` 的现有启动方式，并增加首次管理员初始化提示或对应本机命令。启动器使用公开且无账号内容的状态探针检查实例，不能再依赖匿名读取管理员报告来确认服务身份。

Docker/Caddy 使用同一认证入口与持久化根目录，代理路径覆盖认证和管理接口。生产注册与登录使用 HTTPS，会话配置不能被 `QUANT_REQUIRE_AUTH=false` 关闭。账号库及所有用户目录纳入私有备份，静态资源仍独立构建与发布。

更新使用手册、维护说明、API 说明和部署模板，说明管理员初始化、名额口径、用户隔离、密码恢复、认证启动与备份。不上线公网、不创建真实用户密码，不自动停止正在执行付费任务的现有进程。

## 9. 验证方法

沿用项目已清理持久化测试目录的约束，在临时目录运行可重复的验证程序，不新增遗留测试输出。只使用临时账号库和临时业务数据库，不向现有账户写入验收数据。

认证验证覆盖正确和错误密码、重复账号、满额、并发最后一个名额、会话到期、退出撤销、修改密码撤销、CSRF 和 Origin 拒绝、普通用户后台 403。并发名额测试至少以两个独立账号仓库连接竞争，覆盖数据库事务边界。

隔离验证创建两个普通用户，分别写入自选、账本或持仓及模型选择；验证读取结果独立，跨用户报告 ID 和截图会话 ID 不可用。管理员现有数据绑定使用临时模拟旧目录，验证新用户不会继承旧内容。

后台验证检查列表账号字段、统计口径、名额和最后登录时间，并断言响应不含财务明细、路径或密钥；概况读取不能调用外部模型。

浏览器验证覆盖注册、登录、业务深链接、退出、切换账号、普通用户隐藏后台入口、管理员概况和手机布局。完成后执行后端源码检查、前端 lint、格式检查与构建。项目原有交易准入状态独立报告，不把认证验证描述为交易准入通过。
