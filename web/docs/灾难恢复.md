# 灾难恢复总手册（batch5-C#8）

> 本文档是灾难恢复的总入口：RTO/RPO 目标、演练日历、一页速查表在此定义；
> 各环节的操作细节保留在原文档中，**只引用、不重复**。

## 1. RTO / RPO 目标（建议值，待运维确认）

| 场景 | RTO（恢复时间目标） | RPO（数据丢失容忍） | 依据 |
|---|---|---|---|
| 单机故障（服务/系统盘损坏，备份完好） | ≤ 4 小时 | ≤ 24 小时 | 每日 02/03/04 点自动全量备份（`quant-backup.timer`） |
| 数据库逻辑损坏（误删表/坏迁移） | ≤ 2 小时 | ≤ 24 小时 | 同上；回滚用 `.down.sql` 迁移（见《迁移规范》） |
| 备份加密密钥丢失 | ≤ 8 小时 | 0（历史归档不可读） | 旧密钥归档保留（见 §4）；私钥离线保管 |
| 异地灾难（本机全毁，异地副本可用） | ≤ 24 小时 | ≤ 7 天 | 异地同步按周执行（`offsite.example.sh` 模板，建议每周日 06:00） |

> 说明：RPO ≤ 24 小时依赖每日备份定时器正常运行；异地 RPO 依赖异地同步已启用
> （默认模板为禁用，需按 `ubuntu-runbook.md §6` / `web/docs/维护说明.md §7` 启用）。

## 3. 演练日历

| 周期 | 事项 | 执行方式 | 通过标准 |
|---|---|---|---|
| 月度（每月 1 日 05:00） | 恢复演练 | 自动（`quant-restore-drill.timer`）；人工每月检查一次结果 | 管理后台备份页 `restore_verified=true`，且当月无失败告警 |
| 季度（1/4/7/10 月） | 密钥轮换检查 | 人工：确认私钥离线保管完好、旧密钥归档可读、判断是否触发轮换条件（经办人变更/疑似泄露/演练失败怀疑密钥问题） | 检查记录留档；触发条件命中则立即执行轮换 |
| 年度（每年 10–12 月） | 分区演练 | 在测试环境完整跑一遍 0035 分区重建（含 `preflight-partition.sh` 预检 + 回填校验） | 预检全过、行数校验一致；更新本手册的预估停机窗口 |
| 年度（配合密钥例行） | 密钥例行轮换 | `rotate-backup-keys.sh`（每 12 个月，见维护说明 §7） | 新加密副本就位、environment 公钥已更新、异地已同步新副本 |
| 按需 | 异地恢复演练 | 从异地下载归档 → 解密 → 恢复到隔离环境 | 数据可读、核心表抽查通过 |

## 4. 一页速查表

```

systemctl status quant-api quant-worker@* # 看服务状态
journalctl -u quant-api -n 100 --no-pager # 看日志
systemctl restart quant-api # 重启（先看日志再决定）


1. 停服务：systemctl stop quant-api quant-worker@*
2. 找最新备份：ls -t $QUANT_BACKUP_DIR/quant-site-*.zip | head -1
3. 解密（如加密）：age -d -i /root/.age-backup-key.txt -o /tmp/site.zip xxx.age
4. 恢复：web/backend-dotnet/deploy/restore.sh /tmp/site.zip <新目录>
5. 核对账号/持仓/现金/日期后重启服务


systemctl list-timers quant-backup.timer # 看下次触发
journalctl -u quant-backup.service --since today # 看失败原因


看 <archive>.restore.json 的 redacted 错误 + journalctl -u quant-restore-drill
可选 webhook：QUANT_RESTORE_DRILL_ALERT_URL（/etc/quant/environment）


web/backend-dotnet/deploy/rotate-backup-keys.sh --dry-run # 先演练
QUANT_BACKUP_DIR=..../rotate-backup-keys.sh # 正式轮换
轮换后必做：更新 /etc/quant/environment 的 QUANT_BACKUP_AGE_RECIPIENT、
新私钥离线保管、重跑一次异地同步


web/backend-dotnet/deploy/preflight-partition.sh # 预检全过才继续
需停机窗口；旧表保留至行数校验通过后再清理
```
