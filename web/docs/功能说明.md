# 量化宝网页版功能说明

版本日期：2026-10-05。本文按当前源码和实际网页功能编写，适用于H5网页。
主要场景是支付宝场外基金的持仓管理、费用核对、研究与AI复核；同时保留股票行情与AI选股研究。

## 1. 功能地图

| 页面 | 入口 | 主要功能 |
| --- | --- | --- |
| 持有 | 首页、主要导航“持有” | 账户快照、持仓、估值、收益提示和截图导入 |
| 自选 | 主要导航“自选” | 基金、指数、股票自选及行情同步 |
| 行情 | 主要导航“行情” | 指数、基金榜、板块，分区刷新和筛选 |
| AI选股 | 主要导航“AI选股” | 股票候选筛选、AI复核及早间报告 |
| 基金复核 | 主要导航“基金复核” | 场外基金AI报告、候选基金评分 |
| 策略 | 主要导航“策略” | 基金策略对比、建议跟踪、组合风险、股票参数和验收记录 |
| 资讯 | 主要导航“资讯” | 资讯列表、检索、阅读状态与来源链接 |
| 基金详情 | 点击基金名称 | 正式净值、K线、费率、申赎、持有批次和公告 |
| 截图导入 | 首页“截图导入基金” | 多图OCR、名称与代码匹配、核对和确认保存 |
| 账本 | 持有/持仓相关入口 | 净值入账、成交、定投、分红、公司行动和记录更正 |
| 持仓明细 | 持有相关入口 | 持仓明细、分类及账户数据核对 |
| 设置 | 齿轮、侧栏“连接设置” | 后端连接、模型发现与选择、系统定时状态和运行趋势 |

较宽屏幕使用侧栏，窄屏使用底部导航。页面内的分区导航用于快速跳到对应模块。
基金详情、账本及截图导入是任务页面，不将全部功能堆在策略页。

账本包含平台快照对账、处理说明和历史成交补录预览。已保存的对账记录可重新打开完整差异、费用依据和处理说明，并下载CSV；账本或平台快照变化后，旧差异仍保留，需重新对账后处理。补录从已确认完整账户基线回放成交、分红、公司行动、冲正和资金事件，并重算原已保存净值序列；不会运行策略或生成历史成交建议。原始记录保留，修订追加审计，历史回算不计入前向模拟天数。

账本“完整历史记录”按交易与分红、公司行动、冲正分类查询，每页50条。可按代码和北京时间日期筛选，包含首尾日；修改条件后需重新查询。CSV导出全部筛选记录，最多10万条，保留精确小数和ISO时间；超限提示缩小范围。账户切换或离开页面清除记录与筛选输入，迟到查询和导出结果不恢复旧数据。

账本“成交导入”可下载十列CSV模板，导入已确认的股票、基金成交，最多1 MB、1,000笔。先在本地逐笔核对，再查重并预览现金、持仓和历史净值变化；已有内容一致的成交跳过，编号冲突或缺少完整历史证据整批阻断。明确确认后原子入账，下载逐笔回执并继续平台账户对账。需要已确认基线和已登记标的，实际时间含时区并严格递增；分红、转换和资金划转使用对应入口。具体字段和验收见[历史成交批量导入说明](refactor/native-ledger-csv-20261008.md)。

“成交导入→已保存的成交导入回执”可以按入账时间分页找回过去的批次，查看新增和跳过记录、原CSV行号、成交编号与账本记录编号，并再次下载完整回执。刷新或重新登录后仍可查询；读取回执不再次入账或调用模型。回执保存导入当时的结果，后续账本更正应同时查阅更正审计。

金额展示直接处理接口返回的十进制字符串，按分四舍五入，不丢失大整数的小数精度；小于半分的正负金额均显示零。首页、持仓页的资产、现金和截图持仓总额先精确求和再显示，不逐项按分舍入；金额缺失时总额保持未知。账本存储和CSV原始精度不改变；分析估算已经以浮点数计算的结果仍按其原值展示。

设置包含登录会话维护、按服务商真实用量计费的模型成本和个人提醒中心。最近调用显示角色、提供方、调用阶段及费用未知原因，费用使用调用时的单价快照。已结束且费用未知的调用可逐笔补录实际服务商账单金额，必须明确确认金额、货币和依据；原始token、调用时单价和未知原因保留，重复提交相同依据幂等，已有费用不能覆盖。没有账单继续保持未知，不从未来单价倒推历史费用。上线与策略验收面板分别显示服务部署条件、策略准入和费用证据，正式HTTPS检查须实际使用配置域名访问。管理员后台包含详细用户数据、实际使用时间线、30天操作趋势、恢复码、运行任务及完整站点备份状态，并显示最近5分钟请求P95、数据库锁等待、每分钟队列趋势、失败摘要及保留清理结果。费用未知不按零计算，净值或高水位不足时回撤未知。

## 2. 账户与持仓

首页显示当前读取到的账户资产、持仓、估值和数据日期，支持全部、基金、股票分类。
持仓快照日期、正式净值日和盘中估值采集时间分别展示，不能互相替代。

系统区分以下数据：

| 数据 | 含义与使用范围 |
| --- | --- |
| 截图持仓快照 | 用户核对的截图时点持仓；不自动视作完整账户和全部交易历史 |
| 完整账户基线 | 经确认的持仓、现金和核对日期，是账本资产及收益核算的起点 |
| 正式基金净值 | 基金披露的单位/累计净值，有自己的净值日期 |
| 盘中估值 | 参考性估算，不能冒充正式净值或实际成交价 |
| 历史缓存 | 上次取得的真实数据；保留原日期，不能冒充本次更新成功 |
| 演示模式 | 未连接服务时的界面示例，明确标注演示，不作为交易证据 |

账户日期异常、净值基线未确认或数据过期时，页面显示具体状态。
没有新数据时显示未知或旧记录，不把缺失收益填成零。

## 3. 截图导入与OCR

操作流程是“选择图片→识别→核对→确认保存”，支持一次最多6张持仓截图。
后端接受PNG、JPEG、WebP，单张不超过6MiB。
图片会发送给配置的OCR服务；本项目不保存上传原图，记录识别和确认所需的结构化结果与指纹。
这不等于外部OCR服务承诺不保存图片，外部服务行为应按其实际设置核对。

识别范围包括基金名称/代码、份额、市值、成本等截图中可辨认的信息。
基金名称匹配可提供候选代码；A/C份额不同，需要用户核对，不能只凭相似名称自动确认。
缺少代码、份额或存在矛盾时，允许修改、补充并重新核对。

公开净值可补充基金净值日期，并按准确份额估算对应净值日的市值；
个人成本、真实现金、实际交易费用及缺失的历史批次不能从公开接口还原。
重复图片、重复记录、持仓变化与保存冲突有对应检查；识别成功本身不写入真实持仓。
手动录入完整账户是备用入口，不要求每次都必须上传图片。

## 4. 自选

基金、股票、指数使用明确的资产类型，避免相同6位代码被当作同一种标的。
支持搜索已有标的、添加自定义代码和名称、星标加入/移出、分类筛选及刷新报价。
已连接时同步服务端自选；同步失败保留本机副本并提示重试。
同步或读取中阻止重复写入；价格、涨跌幅、正式净值日和报价时间按标的类型展示。

筛选、清除和列表展开立即在已有数据上完成，不额外等待行情请求。
切换服务连接会隔离原连接的数据和缓存，不能拿旧连接的记录授权新连接的模型请求。

## 5. 行情与资讯

行情页按指数、基金榜、板块分别展示、检索和刷新，某个分区失败不清空其他已取得的数据。
行情来源包括当前配置的公开数据提供者；来源状态、采集时间、缓存与缺失状态可区分。
指数/板块支持查看详情提示，基金榜可进入基金详情。

资讯页支持检索、阅读状态、列表分批展开和查看来源。
后端包含财联社及其他公开来源的读取适配，实际取得的来源以页面及服务状态为准。
这些适配不能视为购买了官方数据授权或获得了保证可用的商业接口。
公开来源超时、限流或结构变化时，会显示失败或保留上次结果。
单纯浏览资讯不会自动调用大模型；新建AI报告是单独的操作。

## 6. 基金详情、曲线与K线

基金详情展示单位/累计净值及历史曲线、阶段净值变动、持仓披露、基金经理、公开费率、
申赎规则、公告、基金档案、生命周期预警、风格漂移和各数据来源状态。
分区分别读取；部分资料失败时，其他已取得的资料仍可查阅。

净值K线支持日K、周K、月K、年K及单位/累计净值序列：

| 周期 | 计算方式 |
| --- | --- |
| 日K | 当日已公布净值作为开、高、低、收，不是盘中成交K线 |
| 周K | 按周一开始的自然周聚合已公布净值 |
| 月K | 按自然月聚合已公布净值 |
| 年K | 按自然年聚合已公布净值 |

聚合周期的开收来自首末有效观测，高低来自区间有效观测；缺失观测不会补成虚假价格。
鼠标、触控及左右方向键可查看观测；Home/End可到首末观测。
累计净值变动、单位净值变动和用户扣费后收益是不同口径，不能混用。

## 7. 实际费率核对

“公开费率”用于查看基金公开资料；“支付宝实际费率”用于用户确认自己的实际收费条件。
公开展示费率不会直接变成已核对的个人费用证据。

支持份额类别、实际申购费率、金额分档费率/固定收费、销售服务年费率、
按持有天数划分的赎回费率、核对日期、生效日期和确认依据。
用户需要明确确认后保存；读取失败或保存结果不确定时，需要重新读取核对。
旧记录、生效条件及近期核对要求均由服务端检查，不因页面看见一条旧记录就放行。

销售服务费不能与净值已包含的费用重复扣除；历史研究中的假设费率也不能冒充支付宝实际费率。
实际费用以用户核对的有效证据及基金/平台当时适用规则为依据。

## 8. 持有批次与赎回试算

用户逐批登记确认单编号、买入确认日、剩余份额、核对日期和依据，并确认全部剩余批次。
批次份额合计需与已确认持仓一致；持仓或批次改变后，需要重新核对。

试算时由用户按照平台规则选择参与的批次和份额，填写预计确认日与规划净值。
系统按持有期限和已核对的费率计算各批次费用及预计净额。
重复批次、超额份额、缺少有效费率或批次证据时阻断。
试算不会替用户选择支付宝实际赎回顺序，也不会向平台提交赎回。

## 9. 账本与净值入账

账本支持买入、卖出、定投、现金分红、红利再投资、基金转换、拆分折算及转托管等已发生记录。
成交信息包括标的、日期/时间、份额、价格、费用和相关核对依据；网页提交的是本地记录，不是下单。
份额、现金余额、日期顺序、完整账户基线和相关证据由后端核对。
提交失败不会靠前端把账户改成“成功”；提交结果不确定时，需要重新读取记录，避免重复记账。

“基金净值入账”先预览正式净值，再由用户确认保存资产与收益曲线。
首次入账需要完整账户基线；过期净值、缺失净值和未知资金流不会被默认为已核对。
账户快照收益、后续成交收益和分红分别归因，避免把导入快照当作实际买入。
记录更正使用更正/冲正记录保留审计关系，不静默改写原成交事实。

## 10. AI选股

选股页使用已保存的股票策略参数筛选候选，展示行情日期、排名股票池、候选、评分和限制。
候选数量、持仓数量、目标权重、排名退出阈值、成本止损和成交额限制在“策略”页配置。
筛选结果支持搜索、筛选、列表展开以及查看单个候选信息。

“筛选候选”和“发起AI复核”是不同动作；前者不意味着调用付费模型。
旧候选缓存仅供查看，不能授权新报告。发起复核前需重新核对当前连接、参数和候选快照。
AI复核走配置的资讯整理、策略、风险复核和最终Jev判断，不在某个模型回答后直接下单。
早间定时报告也在此板块读取，历史报告可以按日期和类型查阅。

## 11. 基金复核

基金复核页展示14:30场外基金报告和基金候选评分，输入来自已确认持仓、自选及公开基金证据。
报告包含摘要、结论、风险、参考来源、数据日期、模型阶段、失败或阻断原因。
候选评分帮助比较当前基金研究维度，分数并不代表预测收益或确定的买卖机会。

基金复核需要区分持仓快照、确认批次、有效实际费率、申赎规则及策略回放证据。
缺少必要资料、数据过期或模型阶段未通过时，只能保存观察/阻断结果。
用户不需要为了看行情上传截图，但没有真实账户资料时，系统不能可靠给出该账户可执行的基金交易指令。

## 12. 模型连接、发现和选择

| 角色 | 工作 | 连接 |
| --- | --- | --- |
| 资讯整理 | 整理当前采集的资讯与引用 | 用户提供的兼容模型API |
| 候选与策略 | 形成候选与策略草案 | 同一用户兼容API |
| 风险复核 | 复核风险、限制和证据 | 同一用户兼容API |
| Jev判断 | 作最终选项判断 | 独立的官方Jev连接 |

设置页接受用户的模型服务地址和API Key，向服务端发起模型发现，再由用户选择角色模型并保存。
前三个角色使用发现的模型列表；Jev模型对应独立连接，不把兼容API返回的普通模型当作Jev。
模型列表能读取成功，不保证每个模型都支持项目要求的结构化输出和报告格式。

API Key只提交服务端保存，网页不回读明文，也不将模型Key写入浏览器存储。
网站使用账号密码及会话Cookie；每个用户分别保存自己的兼容API和Jev官方Key。模型Key不能替代网站登录。
读取模型列表和保存选择不会创建AI报告，但模型服务自己的目录查询费用规则仍由服务商决定。
新报告冻结创建时的四个角色模型；以后修改配置不会重写旧报告。
正在执行报告时阻止配置覆盖，并使用配置版本检查避免多个页面互相覆盖。

## 13. 基金策略对比与曲线

“策略→策略对比”比较同等起始预算下的买入持有、分期投入和月度趋势观察。
可以切换基金、前后段样本和假设费用情景，查看扣费后收益、最大回撤、超额收益、
估计费用、买卖次数、平均投入以及资金/回撤曲线。
曲线支持鼠标和键盘查看观测点，缺失观测会明确标示。

“更新研究”重新采集公开基金资料并计算，显示版本、生成时间和净值截止日期。
更新失败保留上一份可读取结果；“重新读取”只读取存档。
公开净值研究与策略验收分开：费用假设、申赎历史、净值公布时间及公司行动等限制保留在结果中。
某个假设情景收益为正，不能把真实交易准入改成通过。

## 14. 建议跟踪与组合风险

早报及基金复核先点击“检查资料”，预检不调用模型、不占报告额度。结果显示缺项和对应处理入口，有效期两分钟；切换账号、离开页面或刷新资料后清空。资料不足时可明确选择“仍生成研究报告（调用模型）”；模型配置、并发、次数额度及金额预算仍在生成时由服务端核验。当前连接没有可靠调用费用上限，启用金额预算会在创建报告前拦截，不消耗报告额度。

“基金复核→执行回放”可下载未核对的 JSON 模板，填写历史交易日历、净值及公布时间、申赎状态、真实费率、结算规则、订单和六类已核对证据。证据包最多2 MB、1,000笔订单及10,000个交易日；金额、份额、净值使用字符串，时间包含时区。回放按申请日净值、确认日和到账日计算费用与在途资金；存在持仓、在途资金或拒单时不输出完全结清扣费收益。公司行动、金额限购、服务费返还及混合持有批次等尚不支持的情况明确阻断。

执行回放冻结输入、结果和指纹，归档仅属当前账号；可读取、导出或在确认后删除，最多保留20份。回放不修改交易账本。归档通过不等于策略准入通过，也不自动关联为某份AI建议的实际成交业绩。

选择 JSON 证据包后可展开“从 CSV 导入历史订单”，下载五列表头模板。CSV 使用 UTF-8 逗号分隔，最多1 MB、1,000笔；申购 buy/add 填金额、份额留空，赎回 sell/reduce 填份额、金额留空或零。小数最多8位，不接受科学计数法；申请时间含时区并按真实时间排序。格式错误标明原文件行号，成功后每页20笔核对，明确点击“确认替换订单”才替换当前草稿中的订单。日历、净值、费率和证据核对状态保持；这一操作不自动回放或记账。

同一份已选择的草稿重试回放会读取同一归档，不重复占用名额；重新选择 JSON 或确认替换订单后使用新请求编号。服务端拒绝把另一份证据归入已有编号。损坏归档仅显示编号、系统记录时间及校验失败提示，不显示其基金或结果；可单独删除，其他归档仍可读取。

“建议跟踪”保存原始AI判断及最终Jev选项，并在后续正式净值记录到齐后展示对应窗口的净值变动和回撤。
观察窗口按有效净值记录计数，不能把“若干条净值后”误写成若干自然日。
原始报告被冻结；后续观察追加，不反向修改当时的模型判断。
尚未收齐记录时显示已取得和仍缺少的数量。

跟踪结果是建议效果观察，不等于用户已成交的收益。
“组合风险”读取当前确认的基金持仓和相关证据，展示组合风险及缺口；缺失数据不会冒充零风险。
因子持续监控、宏观证据和组合基准提供研究信息，不自动修改持仓。

从首页账户汇总进入持仓复盘，点击本页“行业归因”，可配置自定义基准、生成归因报告和读取历史报告。
“策略→研究监控→组合基准”也可新建或编辑基准。成分权重填百分数，1至20个成分合计100%；股票使用完整代码（如600000.SH），现金使用CASH。
可设为当前账号默认基准；自动归因仍需明确选择所用基准。修改基准影响后续计算，已保存报告保留生成时的基准和来源证据。

自动行业归因支持股票、基金与现金、自定义固定成分基准，要求已确认原始基线、当时已知行业，以及每个期间边界准确、已验证的正式收盘价格或基金净值。固定持仓模式计算股票价格及基金净值收益，区间内存在交易或分红等变化时显示缺项。
“根据账本生成分期报告”按可审计交易、现金分红、已确认存取款、公司行动和冲正的生效日期重建持仓，计入实际成交差额与费用，并保存分期报告和连结结果。支持拆分、红利再投资、基金转换和转托管；冲正保留原始事件，按冲正生效日恢复数量与现金。存取款按期末流量中和，不等同于日内精确时间加权收益；期初无持仓标的的成交差额及分红归入现金贡献。最多366个期间；缺少价格、审计、资金不足或存在手工持仓覆盖时阻止生成。

基金行业归因按期初已经观察到、且距期初不超过180天的历史披露持仓，将基金净值收益和事件贡献按行业权重分摊。未披露部分单列“基金未披露”，不推断其行业或底层股票实际交易收益；后来披露的持仓不能回填期初。缺少历史披露或准确净值时显示缺项。官方指数历史成分仍须提供独立证据，当前基准继续使用用户保存的固定成分。
手工归因可填写同一区间的行业期初权重和收益。两边权重分别合计100%，现金需纳入。

多期归因可在“已保存的归因报告”中跨页选择2至60份已完成单期报告，使用同一组合和基准，前一期结束日期须等于下一期开始日期。生成后按时间顺序连结，每期保留自己的权重；页面展示复利累计收益、累计行业效应，以及冻结的单期输入与来源。多期报告不能通过单期重新计算接口覆盖；调整来源后需生成新报告。

手工选择的多期连结只使用所选已保存证据，原单期的来源限制继续有效；有外部资金流时各期收益须先正确中和资金流。账本模式自动生成的单期和连结报告保留冻结来源，不能用单期重算覆盖。
“读取报告历史”按时间倒序分页显示当前账号的报告，可按组合/基准/报告ID、来源和日期范围筛选；日期筛选要求报告整个区间位于所填范围内。点击已完成报告读取行业明细与来源，无需另行记住报告ID。“选择唯一的下一期（本页）”仅在当前页存在唯一连续同组报告时自动选择，多个版本需自行核对。
已保存报告可导出行业明细CSV和完整来源JSON，保留原始小数比例。多期CSV只列累计效应，不填造不存在的统一权重；JSON包含冻结单期输入、账本证据与来源关联。

当前内置交易日历覆盖2026年；10–12 月若缺次年日历，调度器自动调 worker 的 `calendar.generate_next_year` 生成待确认版本（美/日/港为规则计算，中国为农历+调休启发式估算，采用前需与官方公告核对；管理员在日历页确认后生效）。QUANT_CALENDAR_AUTO_ACCEPT=true 时交易日判定可采纳未确认的自动日历；其他年份无法确认时停止自动执行。

### 交易日历自动生成与 provenance 约定（2026-10-21 起）

- Worker op `calendar.generate_next_year` 可按市场（CN/US/JP/HK）生成次年休市日（算法来源见 op 返回的 `source`/`confidence`/`notes`），写入 `site_settings` 的 `calendar:<market>:<year>` 键。
- 自动生成的日历 JSON 必须携带 provenance：`origin="auto"`、`confirmed=false`，以及 `provenance` 对象
  `{"generated_by":"calendar.generate_next_year","generated_at":"<ISO8601>","source":"lunar_algorithm|nyse_rules|japan_law|hkex_rules","confidence":"high|medium|low","notes":["<需人工核对的启发式估计说明>"]}`。
- 管理员按交易所官方公告核验并重写后，`origin="imported"`、`confirmed=true`（source 为官方公告 URL）。
- `QUANT_CALENDAR_AUTO_ACCEPT`（默认 `true`）：`true` 时 TradingDay 采纳未确认的自动日历；`false` 时必须人工确认，否则按日历缺失处理（跨年自动报告暂停）。
- `site_settings` 的 `calendar_policy` 键存跨年份政策：`auto_accept`、`rollover_months`（默认 `[10,11,12]`，进入这些月份后提示准备次年日历）、`confirmed_years`（已人工确认的年份列表）。不做此政策键的手工改表结构。
电脑休眠、关机或后端未运行时不能执行调度；仅打开网页并不保证后端一直运行。
微信推送仍暂缓，系统不执行券商或支付宝自动交易。

本次清理后的现有数据仍为3/9，清理测试或旧文件没有让缺少的真实证据自动通过。

## 19. 账本更正的顺序保护

成交、分红冲正不能早于原记录或当前账本日期，不把账户状态倒退到过去。
买入之后存在尚未冲正的卖出时，不能直接扣掉原买入成本；需先核对关联卖出。
成交后已有份额拆分、基金转换、持仓重新确认或完整账户校准时，原份额/成本不能直接套用。
系统阻止这类不可靠更正并返回中文原因，失败时持仓、现金、原记录和审计状态均不变化。

正常的后续加仓以及先处理关联卖出后的冲正仍可以使用；已保存的平均成本按数据库6位小数精度核对。
费用与净值证据、用户选择模型、系统调度和九项交易准入不因这些修复改变。

## 20. 资金计划

从“持有→快照资产→资金计划”读取已有计划或新建计划，填写存入/提取方向、金额、频率和起止日期。支持单次、每周、每月、每季度及每年；可编辑、暂停、恢复或完成。

输入查询日期可查看当天生效的资金安排。月底和闰年按起始日排期；例如1月31日的月计划在2月末执行，3月仍为31日。列表每页20条，可按生效、暂停、已完成筛选并翻页；预览为起始日起365天内的前12次，当天查询不受列表分页限制。

金额最多8位小数。保存失败可重试；并发修改提示重新读取，避免覆盖另一处修改。资金计划不自动转账或记账，实际到账后需在交易账本确认资金流。

## 21. 批量二期新功能（2026-10-21 起）

以下八个功能按 batch2 跨流契约（`qr2-contracts.md`）编写；后端/Worker/前端实现
分属 A/B/C 流，页面细节以上线版本为准。通用约定：用户业务写操作记
`user_operation_audit`，管理员操作记 `admin_audit`（带哈希链，见 §22）；新错误码
先在 Core/Errors 注册，沿用全局异常中间件与冻结错误码。

### 21.1 组合再平衡（页面 /rebalance，接口 api/v1/rebalance）

按用户设定的目标权重检查当前持仓偏离，给出调仓建议（买入/卖出标的与金额）。
建议是测算结果，不下单、不修改持仓；实际调仓仍走账本手工记录。
再平衡不改变九项交易准入与费用证据要求。

### 21.2 估值仪表盘（页面 /valuation，接口 api/v1/valuation）

展示指数的 PE/PB 及其历史百分位（`pe_pct`/`pb_pct`）、股债收益差（ERP）与综合
温度计（`temperature.score`/`label`）。百分位默认回看 10 年，可配。
结果缓存 `QUANT_VALUATION_CACHE_TTL_MIN` 分钟（默认 360），缓存期内重复查看不重算。
百分位是历史分位描述，不是买卖建议；不保证盈利。

### 21.3 赎回费率提醒（接口 api/v1/valuation 归属外，独立提醒）

按持有批次计算每笔份额当前赎回费率档位、下一降档时点与预计可省费用
（`days_left`/`save_estimate`）。`QUANT_REDEMPTION_REMIND_DAYS`（默认 14）天内
即将降档的批次进入提醒列表。费率口径与赎回试算一致（Python `funds/fees.py`
与 C# `FundFeeRules` 已锁定一致，见 E4）。提醒不替用户选择赎回顺序，
不向平台提交赎回。

### 21.4 基金体检（页面 /health，接口 api/v1/funds/health）

对自选/持仓基金做四项检查：规模变动（`scale_change`）、基金经理变更
（`manager_change`）、风格漂移（`style_drift`）、费率水平（`fee_level`），
每项按 `info`/`warn`/`critical` 分级并附证据说明。默认每周一 06:00
（`QUANT_HEALTH_CHECK_CRON`，北京时间）自动跑一次，结果在页面查阅历史体检报告。
体检是公开信息整理，不构成调仓建议。

### 21.5 智能定投（页面 /smart-dca，接口 api/v1/dca/smart）

按估值温度计自动调节每期投入额：低估多投（`low_pct_boost`）、高估少投
（`high_pct_cut`）、极端高估暂停（`halt_pct`）。页面提供回测：给定指数、
起止时间与基准金额，复用现有回测引擎口径输出投入总额、终值、年化（XIRR）、
最大回撤与资金曲线。回测是历史情景测算，不承诺未来收益；定投计划本身不自动
扣款转账，实际投入仍需用户手动执行并在账本记录。

### 21.6 组合回测（页面 /portfolio-backtest，接口 api/v1/backtest/portfolio）

对一组基金按权重做历史组合回测，支持按周期（1M/3M）或偏离阈值再平衡，
可叠加定投现金流。输出组合指标、净值曲线与再平衡事件清单。
口径与“策略→策略对比”一致：费用假设、申赎规则与净值公布时间以回测输入为准，
缺失观测明确标示不补造。回测通过不等于策略准入通过。

### 21.7 自然语言问答（接口 POST api/v1/ask，全局问答小组件）

用一句话问账户与持仓问题。命中 10 个预置问题模板的走确定性账本查询：
不调用模型、零成本、答案来自账本查询；近似指标会在答案中说明口径。
未命中模板时返回 `matched:false`、`unsupported:true`、`model_calls:0`，
列出支持的快捷问题并提示前往 AI选股或基金复核，不调用尚未实现的模型任务。
问答只读，不修改数据；退出、切换账户或认证失效时清除浮窗历史与草稿，
旧会话的迟到响应不能写入新会话。核验会话期间隐藏私人内容，同一会话核验后恢复。

### 21.8 公告聚合（页面 /announcements，接口 api/v1/announcements）

聚合自选/持仓基金的公开公告：分红（`dividend`）、基金经理变更
（`manager_change`）、清盘风险（`liquidation_risk`）及其他，展示标题、
发布时间、来源链接与摘要。可按基金与起始日期筛选。公告来自公开来源整理，
不是购买的官方数据授权；来源超时或结构变化时显示失败或保留上次结果。

## 22. 管理员审计哈希链（2026-10-21 起，任务12）

`admin_audit` 新增 `prev_hash`/`hash` 列构成哈希链：
`hash = SHA256(prev_hash||actor_id||action||target_id||detail||created_at_utc)`，
`created_at_utc` 为 UTC 的 `YYYY-MM-DDTHH24:MI:SS.ffffffZ` 格式，NULL 视为空串，
创世行 `prev_hash` 为空。所有管理员写入统一走 `AdminAuditRepository` 计算入链。
管理员后台提供“验证审计链”（`GET api/v1/admin/audit/verify`）；运维可用独立脚本
`web/backend-dotnet/deploy/verify-audit-chain.sh` 直连数据库逐条验算，
断裂或哈希不匹配即报失败（退出码非 0），用法见[维护说明](维护说明.md) §15。

## 23. 批量三期新功能（2026-10-21 起）

以下功能按 batch3 跨流契约（`qr3-contracts.md`）编写；后端 A 流负责的
接口与服务。通用约定：管理员操作记 `admin_audit`（哈希链，见 §22）；
限流、告警与模型缓存为工程能力，配置走 `QuantOptions`。

### 23.1 风险指标（接口 GET api/v1/risk/metrics）

组合风险指标由 worker op `risk.metrics` 计算（契约：VaR=历史模拟法 95%），
后端按 60 分钟缓存（`QUANT_RISK_METRICS_CACHE_TTL_MIN`，默认 60）。
`period_days` 默认 365，可选 30–1825；`portfolio_id` 缺省为用户主组合。
指标口径（worker 实现，A 端只做透传与缓存）：

- **VaR（历史模拟法 95%）**：按过去 `period_days` 日收益分布的第 5 百分位数，
  含义是“在历史情景下，单日亏损有 95% 概率不超过该值”。历史模拟法不假设
  收益正态分布，直接用历史分位；**局限**：依赖窗口内历史有代表性，窗口外
  极端事件（“黑天鹅”）不在分位内；VaR 不描述尾部亏损大小。
- **最大回撤（max_drawdown）**：区间内组合净值从历史峰值到随后谷底的最大
  跌幅。**局限**：是事后描述，无法预测未来回撤深度与恢复时长。
- **年化波动率（ann_volatility）**：日收益标准差 × √252。**局限**：假设波动
  随时间均匀放大，实际波动率会聚类、突变。
- **夏普比率（sharpe）**：(年化收益 − 无风险利率) ÷ 年化波动率，衡量单位
  风险换来的超额收益。**局限**：分子分母都来自历史，未来无风险利率与收益
  分布会变；收益非正态时意义减弱。
- **卡玛比率（calmar）**：年化收益 ÷ 最大回撤，衡量每单位回撤承担换来的收益。
  **局限**：回撤是单次极值，样本区间不同结果差异大。

以上均为历史测算，不构成收益承诺；测算依赖持仓净值序列完整，无快照区间
的日期明确标示不补造。

### 23.2 压力测试（接口 GET api/v1/risk/stress）

固定三档历史情景（2015 股灾 / 2020-03 疫情 / 2022 熊市），worker 常量
`STRESS_SCENARIOS` 按宽基指数区间跌幅写死并注明来源区间。响应每档给出
指数跌幅（`index_drop_pct`）、组合预估亏损比例与金额，并强制带
`disclaimer: "假想测算非预测"`。**压力测试是假想测算非预测**：情景复制
历史跌幅而非预测未来，实际组合还受个基弹性、申赎与再平衡影响，数字只做
风险意识参考。

### 23.3 邮件推送（接口 api/v1/notify/email/*，迁移 0038）

系统邮件统一走 `EmailDeliveryService.SendAsync(userId, template, payload)` 发送。
SMTP 配置存 `site_settings`（键 `QUANT_SMTP_HOST/PORT/USER/PASS/FROM`、
`QUANT_SMTP_NOTIFY_TO`），未配时回退同名环境变量；`PASS` 仅内存使用，
永不落日志、不出现在任何接口响应（设置接口只返回 `has_password`）。
发送失败指数退避重试最多 3 次（失败后等待 2s/4s）；每次发送（成功/失败/
未配 SMTP 时的 `skipped`）都记 `email_send_log`（`GET api/v1/notify/email/log`
查询，分页）。管理员经 `GET/PUT api/v1/notify/email/settings` 维护配置，
`POST api/v1/notify/email/settings/test` 发测试邮件；修改记 `admin_audit`。

定时报告完成（`advisor_notifications` 中当日已完成的早盘/午盘报告）与
critical 告警（`operational_alerts` 中 `severity='critical'` 的未关闭告警，
每键 24 小时内最多发一次）由 Scheduler Tick 自动发邮件，站内触达
（通知列表/运维告警页）保留不变。

收件人说明：`users` 表没有邮箱字段，单机部署下邮件发往管理员在设置中
配置的 `QUANT_SMTP_NOTIFY_TO`（未配则回退发件人），正文注明归属用户。
微信通道暂缓：顾问设置中 `wechat_enabled=false` 保持不变，当前仅邮件 +
站内触达；后续若接入微信，按同样模板与重试策略扩展。

### 23.4 持有成本（接口 GET api/v1/cost/positions）

按基金展示：持仓成本（`total_cost`=`average_cost`×份额）、当前市值、浮动盈亏
（金额/比率）、加权持有天数（按持有批次剩余份额加权，批次口径见 §8）、
几何年化收益率 `(1+浮动盈亏率)^(365/加权持有天数)-1`、当前赎回费率与赎回费
估算、回本线（`break_even_nav`=`average_cost`÷(1-赎回费率)：扣赎回费后到手
等于成本所需的单位净值）。

费率口径复用 C# `FundFeeRules`（唯一口径，与 §7/§8 赎回试算一致，不另写一套）；
该基金无已验证费率证据时赎回费与回本线留空并注明 `fee_schedule_missing`。
年化仅在有有效批次持有天数（≥1 天）且浮动盈亏率 >-100% 时计算，否则留空
并注明原因。赎回提示含税费文字提示（仅文字，不做税务计算、不构成税务建议）。
数据为测算展示，不下单、不修改持仓。

### 23.5 研报聚合（页面 /research，接口 api/v1/research，迁移 0039）

聚合研报（`report`）与资讯（`news`）：标题、摘要、来源、链接、发布时间、
关联标的。`GET api/v1/research` 按标的/类型过滤分页查询（研报为公开信息，
不按用户隔离）；`POST api/v1/research/refresh` 接受可选 `symbols`（默认用
用户持仓基金代码）与 `kinds`（默认 `report`/`news`），调 worker op
`research.fetch` 抓取后落库，`UNIQUE(url)` 去重，返回抓取/新增条数
（`deduped:true`）。手动刷新记 `user_operation_audit`；Scheduler 每日自动
抓取一次（与公告抓取同模式：日期门控、逐用户、失败不中断 Tick）。
抓取框架与去重逻辑复用 `announcements.fetch`（batch2-8）；源站结构变化时
保留上次结果，不虚构条目。

### 23.6 API 限流中间件

按 用户+IP 双维度固定窗口限流，默认 100 req/min
（`QUANT_RATE_LIMIT_PER_MIN`，1–100000）。超限返回 429（统一错误契约
`rate_limited`）+ `Retry-After` 头（秒，至窗口重置）；响应另带
`X-RateLimit-Limit`/`X-RateLimit-Remaining`。登录/注册/恢复/改密接口保持
既有更严策略（20/min 令牌桶）不动，本中间件跳过这些路径；`/internal/v1`
与非 `/api/v1` 请求不计入。

计数为纯内存实现（单机部署，无需 Redis）：应用重启清零可接受；窗口滚动
惰性清理过期键（键数超 20000 时清 2 个窗口前的旧键）。

### 23.7 慢查询聚合告警

在现有 >500ms 慢日志（`PerformanceMiddleware`）基础上，慢请求按小时桶聚合
（`SlowRequestAggregator`：endpoint 取路由模板 + 慢请求次数 + p95，纯内存，
每桶样本上限 10000，应用重启清零）。Scheduler 每小时评估上一个完整小时桶：
某接口慢请求次数 ≥ `QUANT_SLOW_QUERY_ALERT_MIN_COUNT`（默认 20）且 p95 ≥
`QUANT_SLOW_QUERY_ALERT_P95_MS`（默认 2000）时，向管理者写 critical 告警
（`operational_alerts`，`alert_key=slow_query:{小时}:{endpoint}`，2 小时前的旧
告警自动 resolve），并经邮件通道自动发邮件（每键 24 小时最多一封）。

运维监控（`NativeOperationsMonitor`）复用该聚合：输出 `slow_requests`（当前
小时各接口次数/p95/是否超限）与未关闭的 `slow_query` 告警（critical）。

### 23.8 模型调用去重缓存

`ModelCallCacheService`：键=`sha256(canonical_json({user_id, model_version, prompt}))`，私人结果按账户隔离。
（`canonical_json` 为递归按键排序对象属性、数组保序；Python 侧等价写法
`json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`），
TTL 走 `QUANT_MODEL_CACHE_TTL_MIN`（默认 60 分钟），开关
`QUANT_MODEL_CACHE_ENABLED`（默认 true）。命中时响应带 `cached:true`，
DB 侧审计记 `model_call_cache.hits+1`。
`model_call_cache` 表由流 D 建（0040）；表不存在时降级为内存缓存并记
warning，不抛错（应用重启内存缓存清零）。

当前调用点为分析/报告链路（`POST api/v1/analysis/explain`，
`model_version="analysis.explain/v1"`，同一决策运行+同一补充说明 60 分钟内
复用解释）；问答端点当前不调用模型，也不读取模型缓存。`model_version` 取 op 作用域版本——API 侧不知道 worker 选用的
具体模型，worker 更换模型时须升级版本，否则可能命中旧模型结果；60 分钟
TTL 为陈旧上界。注意：`advisor.report`/`agent.research` 的模型调用发生在
Python worker 进程内，C# 后端无法拦截；B 流如需在 worker 侧去重，
按本节键格式与表接口层面的说明见 §23；本节记录 worker op 的计算口径与缺数据时的降级行为。

## 24. 批量三期 worker 计算方法论（risk/cost/research）

Worker 新增四个 op（`web/worker/risk_operations.py`、`cost_operations.py`、
`research_fetch_operations.py`），通过 `operations.py` 注册供 .NET 后端调用。
四个 op 均为纯计算（`portfolio_id` 路径除外，见下），方法论文档写在各自
docstring，缺数据时返回空 + warning，不虚构。

### 24.1 风险指标（`risk.metrics`，接口 `POST /api/v1/risk/metrics`）

入参 `{portfolio_id, period_days}` 或 `{nav_series: [...]}`（后者便于测试）。
`nav_series` 接受纯数字、`{date, nav}` 或 `[date, nav]` 三种形状，视为每个
交易日一个点。`portfolio_id` 即账本 `user_id`，从 `portfolio_valuations`
读 `(as_of_date, unit_nav)` 序列（需调用方传 `snapshot` 建 DB 上下文）。

- VaR(95%)：历史模拟法，日收益 5% 分位数取反（线性插值，与
  `numpy.percentile` 默认口径一致），下限截 0，正值表示亏损幅度。
- 最大回撤：净值峰值到谷底的最大跌幅（正值表示亏损幅度），同时返回
  `max_drawdown_peak_date`（起）与 `max_drawdown_trough_date`（止）。
- 年化波动率：日收益样本标准差 × √252；夏普 =（年化均值 − 无风险利率）/
  年化波动率，无风险利率取常量 `RISK_FREE_RATE = 0.02`（改一处即可）。
- 卡玛比率 = 年化收益 / 最大回撤（年化收益按 `(末/首)^(252/n)−1`）。
- 序列少于 30 个点时全部指标为 `None` + warning。

### 24.2 压力测试（`risk.stress_test`，接口 `GET /api/v1/risk/stress`）

入参 `{portfolio_id}` 或 `{nav_series, weights}`（另可选 `portfolio_value`、
`beta`）。用写死在 `STRESS_SCENARIOS` 的三档历史极端情景测算当前组合
假想损失（宽基指数统一用上证综指收盘价区间，约值）：

| 情景 | 区间 | 区间跌幅 |
|---|---|---|
| 2015年股灾 | 2015-06-12 → 2016-01-28 | 约 −48.6% |
| 2020年3月疫情冲击 | 2020-01-14 → 2020-03-19 | 约 −15.6% |
| 2022年熊市 | 2021-12-31 → 2022-10-31 | 约 −20.5% |

按组合 beta≈1 简化（默认 1.0，可传参覆盖；响应与 disclaimer 明确标注为
粗估），`est_loss_pct = 区间跌幅 × beta`。`est_loss_amount` 需要
`portfolio_value`（`portfolio_id` 路径取最新 `total_value`），缺则为
`None` + warning。响应固定带 disclaimer：假想测算、非投资建议。

### 24.3 持有成本（`cost.positions`，接口 `GET /api/v1/cost/positions`）

入参 `{funds: [{fund_code, current_nav, lots: [{acquired_at, shares,
cost_amount, redemption_tiers}]}]}` 或 `{portfolio_id}`。逐只基金输出：
持仓成本、当前市值、浮动盈亏（含百分比）、预估赎回费、年化收益率、
回本净值线。

- 费率口径与 `FundFeeSchedule`（`funds/fees.py`）一致：每笔 lot 按持有天数
  匹配 `redemption_tiers`，赎回金额 = 份额 × 当前净值（与
  `fund.redemption_windows` 同口径，申购/管理费腿置零）。
- 年化收益率（XIRR 简化版）：每笔买入视为一次性现金流出、期末市值视为
  一次性流入，复用 `backtest_shared.xirr` 二分求解；忽略期间分红与再投入。
- 回本净值线 =（成本 + 预估赎回费）/ 持有份额；无费率数据时按成本/份额
  并注明未含赎回费。
- `portfolio_id` 路径：从 `transactions` 按时间顺序 FIFO 轧差买卖重建
  lots（lot 成本 = price × quantity + fees），以 `positions` 表倒推当前净值；
  无逐笔交易时退化为按 `average_cost` 的持仓级估算，年化收益率置空并打
  warning（不虚构买入日期）。

### 24.4 研报资讯聚合（`research.fetch`，接口 `GET /api/v1/research`、刷新 `POST /api/v1/research/refresh`）

入参 `{symbols: [], kinds: [report, news]}`，输出
`{items: [{title, summary, source, url, published_at, symbol, kind}], deduped: true}`。
复用 `announcements.fetch` 的抓取框架：可插拔 `_RESEARCH_SOURCES` 注册表、
`http_get` 可注入（测试确定性）、按 URL 去重、失败来源记 warning 不阻断。

默认只用公开免费源（`DEFAULT_RESEARCH_SOURCES`，已验证可用）：
`eastmoney_reports`（东方财富研报中心，kind=report，按 `stockCodes` 查询；
基金代码无对应研报时自然为空）与 `eastmoney_news`（东方财富资讯搜索，
kind=news，按关键词查询）。op 入参 `sources` 可覆盖来源清单，
`kinds` 可过滤研报/资讯。
