# 量化宝原生架构

更新时间：2026-10-17。当前目标为单台服务器，个人或几十名用户，不使用 Docker。

浏览器运行 Vue 3 / UniApp H5 与 TypeScript；Caddy 提供 HTTPS，转发至 ASP.NET Core 10；PostgreSQL 18 保存账户、账本、业务配置、审计、任务状态和费用。Python 3.12 常驻 Worker 复用公开行情、基金详情与展示估值的 Provider；因子、回测与研究计算保留受控子进程。业务主后端采用模块化单体。

## 代码与运行边界

| 目录 | 当前职责 |
| --- | --- |
| `src/QuantAssistant.Api` | 业务控制器、HTTP 契约、会话及权限中间件、应用服务、后台调度 |
| `src/QuantAssistant.Core` | 账本及业务规则、接口、稳定错误契约 |
| `src/QuantAssistant.Infrastructure` | PostgreSQL 仓储、事务、业务快照、计算租约与费用预算 |
| `web/worker` | 命名计算操作；公开展示查询及无 I/O 的策略参数校验在进程内执行，预览与研究等计算启动受控子进程 |
| `web/backend/src` | 复用的 Python 计算与数据适配库，保留旧站点供兼容和回切验证 |
| `web/frontend/src` | 严格 TypeScript 的模型、控制器、Vue 页面与组件 |
| `tools` | 冻结导入、反向导出、原生备份恢复与故障续恢复 |
| `deploy` | Windows 发布和进程树监督、Linux systemd 与 Caddy 配置 |

依赖方向为 Api → Infrastructure / Core，Infrastructure → Core。部分应用编排目前位于 Api/Services，按功能组织；没有新增消息总线或微服务层。原生 API 不通过通用 HTTP 转发调用旧 FastAPI 业务接口。

C# 是正式业务写入方。Python 从经过认证的内部接口领取不可变输入，使用内存 DuckDB 计算；原有 DuckDB 的 12 类分析表只读加载。计算进程移除数据库连接及服务器密钥目录的环境变量。正式净值计算可保存不可变原始来源文件，C# 核验账户、文件哈希和业务状态后才提交数据库。

## 一致性与故障处理

- 金额、份额和费用使用 C# Decimal 与 PostgreSQL numeric，JSON 使用十进制文本；不能表示的精度拒绝，避免浏览器浮点改写。
- 同一账户的账本与证据写入共用事务锁；重复确认返回已提交结果，变化后的预览拒绝提交。
- 计算任务最多全站 3 个并行、每账户 1 个；owner token、attempt、deadline 和租约共同约束心跳、费用授权及结果提交。
- 超时、进程退出或账户停用后，任务转为中断；旧租约不能提交或再次付费调用。大输入写入采用独立线程，监督线程仍检查期限。
- 模型调用在执行前重新核验研究预览并预留预算；未知用量保持未知，有预算时阻断后续调用。
- 会话重新核验账户状态，写操作校验 CSRF 和来源；默认关闭注册，本机初始化管理者后才能开放，账户上限 30。
- 模型密钥由 ASP.NET Data Protection 加密，独立于站点与静态资源目录。普通站点备份排除密钥，密钥和解密材料需另行保护及备份。

## 发布和恢复

`publish.ps1` / `publish.sh` 构建新目录，包含 API、H5、迁移、工具和锁定的 Python 环境。`启动网页版.ps1` 现在运行原生发布版。Windows supervisor 持有进程树 Job Object；Linux worker 由 systemd control-group 管理。业务端口只监听 loopback，外部访问由 Caddy HTTPS 提供。

数据库迁移为 0001–0021。0020 增加匿名公开数据快照、任务时间字段和 PostgreSQL 通知触发器；0021 增加账户及公开展示数据版本，用于提交后立即失效的短缓存。升级时须先执行迁移。正向导入要求空库和冻结来源；账号标识、各用户历史编号、时间与金额保留，旧会话和未完成的付费任务不恢复执行。反向导出从 PostgreSQL 重建旧业务库，设置后续编号，保留分析数据。恢复仅写入新空库和新目录；转储、恢复标记和数据库指纹一次提交，后续写入会阻止中断续恢复。

Windows supervisor 可显式启用每日空闲停服备份，完成或失败后恢复所属服务并等待 worker 就绪。管理后台显示实际与期望 worker 数量、队列、磁盘、归档年龄、备份结果和请求指标。归档完整性校验使用有界缓存，实际恢复证明绑定归档哈希；备份创建成功不能替代恢复验证。

年度交易日历由管理者依据交易所官方公告维护，页面保存携带版本以阻止并发覆盖。当前与次年状态在后台显示，10月起提示次年准备；缺失年份继续阻止自动报告，不能凭空补全年份。

运行与验收说明见 [原生部署及恢复手册](../docs/refactor/p7-runbook.md) 和 [迁移状态](../docs/refactor/native-migration-progress.md)。保留旧源码用于计算复用与回切，不代表原生入口仍运行旧业务服务。

2026-10-17 本地性能改造、完整回归与尚未达标的严格性能指标见 [本地落地与验收记录](../docs/refactor/backend-performance-local-completion-20261017.md)。

## 常用接口性能路径

`PublicSnapshotRefresher` 启动时恢复 PostgreSQL 中的公开快照。生产环境在已核验交易日的上海时间 09:15–15:05 每 60 秒预热大盘、指数、自选、估值及轮换基金详情；启动时也尝试一次。`QUANT_PUBLIC_REFRESH_ENABLED=false` 可关闭自动预热，开发环境默认关闭。预热需要至少 32 字符的 `QUANT_WORKER_SECRET` 和有效账户；不改变计算租约、并发限制或账户权限。主动刷新请求仍可在休市时发出。

行情快照的展示内容纯读内存；行情、估值、资讯和基金详情读取已完成的公开快照。首次没有证据时，行情、资讯和详情快速返回 `503 public_snapshot_unavailable` 和 `Retry-After: 2`，行情及估值逐项列出 `unavailable`。刷新只排队，HTTP 展示请求不等待公网爬虫。上一版可展示证据保留原时间并标记 `stale`，失败和全不可用结果不能覆盖有效大盘。

盘中估值失败后，Worker 只从网关随任务提供的匿名基金详情快照读取最近两个官方净值点，不启动全历史爬虫。点位须有 `eastmoney`、`tencent` 或 `danjuan` 来源、不同有效日期、正的有限净值，且两点均在最近 14 天内。结果标记 `valuation_type=latest_nav`、保留原观测时间和 `local:来源`；有官方 `daily_return` 时保留该值，避免分红或拆分日用净值比值误算涨幅。没有合格本地证据时继续保持不可用。

共享表仅接受公开类型和不含账户快照、凭据的结果。进程内计算缓存仍按用户、操作和输入哈希隔离，使用原完成时间绝对过期并克隆响应。行情、估值和资讯新鲜期 60 秒，基金详情 300 秒；过期详情最多保留 7 天作为明确标记的旧证据。每次 HTTP 请求仍核验会话、账户状态和写权限，不能用展示缓存绕过鉴权。

高频鉴权、持仓、账本列表、历史查询、偏好、聚合和计算队列使用 Npgsql 原生异步 I/O；`AccountDatabase` 保留同步适配器供现有低频领域流程和 CLI 使用。`/api/v1/dashboard/summary` 在一条 SQL 的一致性视图中返回账户持仓、偏好、估值和自选报价，再附加内存行情。概览及持仓的 500ms 缓存按用户与数据版本隔离，并合并同版本并发查询；每次鉴权从数据库读取版本，持仓、标的、账户文档或公开快照提交后立即切换缓存键。每个返回值独立克隆，单个客户端取消不会中断其他客户端的共享读取。Python 分析库通过独立只读事务池查询；写事务仍串行，事务内查询继续读取该事务以保持一致性。

每日用量计数在响应完成后写入最多 4096 项的内存队列，每 50ms 合并后批量提交，数据库行争用不延迟用户接收数据。写入失败重试；关闭时最多等待 5 秒排空；队列满时记录 `quant_usage_counter_dropped_total`。它属于运行统计，不参与财务提交或计费授权。HTTP 压缩由 Caddy 的 `encode zstd gzip` 统一处理，原生 API 不再对小型 JSON 动态压缩。直连 loopback API 的压测与经过 Caddy 的生产链路应分别记录。

线程池由独立线程每 10ms 采样，`quant_thread_pool_pending_peak_10s` 和 `quant_thread_pool_sample_count_10s` 保留最近 10 秒峰值和采样量，另保留当前待执行量。负载结束后为零与负载中每个瞬时采样都为零是不同指标，验收记录须分别报告。

API 和 Worker 以 PostgreSQL `LISTEN/NOTIFY` 及进程内信号即时唤醒。Worker 无任务时服务端长等最多 5 秒；网关等待计算结果仅以 5 秒复查兜底，避免丢失通知，取消和租约检查保持有效。API、Caddy 和 Worker 贯穿 `X-Trace-Id`，`Server-Timing` 给出鉴权、数据库、网关、队列、启动和外部 I/O 耗时；并发阶段可能重叠，不能直接相加。超过 500ms 输出脱敏分段慢日志。开发环境可设置 `QUANT_TRACE_CONSOLE=0` 关闭较重的 OpenTelemetry 控制台导出；普通结构化请求日志继续保留。
